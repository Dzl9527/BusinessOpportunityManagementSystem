# 需求变更记录

## 2026-06-14

### 变更：移动端用户中心综合优化与沙箱功能改进

背景：

- 原有的用户中心（`UserCenter.vue`）在手机端展示时，页面元素较为杂乱，占用大量屏幕空间。
- 手机端本不应暴露管理入口，但原来的界面包含了“管理入口”导致普通用户体验不佳且存在安全感误导。
- 为了开发测试方便，需要提供一个更加显眼的免登身份切换下拉框（沙箱测试环境），以便在不同角色之间进行切换测试。

核心决策：

- **UI 布局优化与空间节省**：将“我的使用说明”和“权限说明”重构为可折叠面板（Collapsible Section），默认在桌面端展开，在手机端折叠，大幅节省手机端首屏空间。
- **角色标识视觉升级**：增加了彩色角色标签（Role Badge），分别对应管理员、领导/白名单用户、普通用户，提升身份辨识度。
- **管理入口隐藏**：通过 CSS 媒体查询，在手机端（最大宽度 900px）强制隐藏管理员的“管理入口”与快捷方式，保持手机端作为纯粹的业务工作台属性。
- **沙箱身份切换**：在用户卡片中新增了沙箱免登身份切换下拉框，内置了测试账号，切换后可自动重载并应用新身份。

影响：

- 提升了手机端用户的操作体验，界面更加清爽专业。
- 开发测试人员能够更快速地在多角色间进行沙箱身份切换与页面功能验证。

关联文档：

- `frontend/src/views/UserCenter.vue`
- `frontend/src/styles/theme.css`

## 2026-05-29

### 变更：智能进度提醒功能落地与系统设置页面重构优化

背景：

- 按照《2026-05-24-用户端商机提报数据结构设计.md》第 13 节的要求，系统需要能够通过企业微信提醒用户持续跟进项目进度，并支持管理员在后台配置提醒天数和启用开关。
- 在前一阶段实现的系统设置页面中，顶部展示的 4 个全局统计卡片与右侧工作区边栏（`workspace-rail`）的“活跃商机”等指标重复，且占用了大量的垂直空间，导致页面显得杂乱。

核心决策：

- **提醒系统实现**：
  - 后端启用了 Spring Scheduling 定时任务调度，每日上午 9:00 自动执行商机进度扫描。
  - 新增 `system_configs` 数据库持久化表，用以持久化配置的提醒提前天数及启用/禁用状态。
  - 判定并实现 7 大提醒场景（提报成功、投标截止、预计交付、周更新超期、授权跟进、报备催办、中标结果补录），并采用 `opportunity_reminders` 历史表进行防重复提醒判定。
  - 对接企业微信自建应用消息接口（`WeComService.sendAppMessage`），并提供沙箱调试打印机制与测试端口。
  - 管理端（`Settings.vue`）提供保存配置和“立即执行提醒扫描”按钮用以实时联调。
- **系统设置界面视觉重构**：
  - 彻底移除了设置页面顶部的 4 个全局统计卡片，节省垂直空间，解决信息冗余。
  - 将与组织权限直接关联的“启用账号”、“管理员账号”、“通讯录人数”收纳到「组织权限管理」标签页中，保持页面干净简洁。

关联文档：

- `docs/requirements/2026-05-24-用户端商机提报数据结构设计.md`
- `docs/changelog/需求变更记录.md`

## 2026-05-26

### 变更：手机端导航命名与管理员入口最终定稿

背景：

- 在完成手机端信息架构梳理后，业务继续确认了最终导航命名、页面排序和管理员入口呈现方式。
- 早期讨论中的“仪表盘”命名和普通用户可见“系统设置”入口，已经不符合最终手机端产品口径。

核心决策：

- 手机端主导航最终固定为：`工作台`、`商机提报`、`商机列表`、`商机看板`、`用户中心`。
- 原 `仪表盘` 页面正式更名为 `工作台`，页面定位保持为摘要、提醒和快捷入口。
- `系统设置` 保留为管理员专属入口，不进入普通用户五大主导航。
- 管理员可通过 `用户中心` 和工作区专属入口进入 `系统设置`。
- 商机列表的大筛选区收口为“折叠筛选”入口，优先保障手机端首屏浏览效率。
- 管理员相关页面需要弱化“工具页”观感，统一向手机端操作界面风格靠拢。

影响：

- 需要同步更新前端导航顺序、页面标题、入口文案和管理员可见范围。
- 需要在需求、产品总览和发布记录中统一使用 `工作台` 命名，不再混用 `仪表盘`。
- 后续如果继续扩展管理员能力，应默认放在 `系统设置` 或 `用户中心` 内，而不是新增普通用户主导航项。

关联文档：

- `docs/requirements/2026-05-26-手机端信息架构与核心页面需求.md`

### 变更：手机端信息架构调整为五个核心入口

背景：

- 当前手机端已经可以访问，但一级导航中仍存在“系统设置”这一偏后台的入口。
- 业务希望重新整理手机端范围，使结构更符合实际使用路径。
- 经确认，手机端第一阶段应重点承接查看、检索、提报和个人账号操作，而不是把后台管理入口直接暴露给所有用户。

核心决策：

- 手机端一级导航统一为：`仪表盘`、`商机看板`、`商机列表`、`商机提报`、`用户中心`。
- `用户中心` 替代 `系统设置` 作为第五个一级入口。
- `用户中心` 支持登录状态展示、个人信息、权限说明和退出登录。
- 管理员相关入口收纳到 `用户中心` 内部，不作为普通用户一级导航直接暴露。
- `仪表盘` 负责摘要和提醒，`商机看板` 负责阶段推进，`商机列表` 负责搜索和筛选，三者需避免职责重叠。
- 商机详情页虽非一级导航，但属于看板、列表、提报后的共用落点，纳入手机端核心能力。
- 手机端第一阶段建议至少覆盖：登录、退出登录、仪表盘、商机看板、商机列表、商机提报、商机详情、基础筛选、权限隔离。

影响：

- 需要调整前端底部导航文案与页面入口结构。
- 需要将“退出登录”从隐含能力升级为明确需求。
- 需要重新审视列表筛选区、长表单分步、空状态和弱网提示等手机端体验细节。
- 产品、前端和后端在后续讨论手机端范围时，应以统一的五入口结构为准。

关联文档：

- `docs/requirements/2026-05-26-手机端信息架构与核心页面需求.md`
- `docs/product/商机管理系统-产品总览.md`

## 2026-05-25

### 变更：OA 商机报备与项目授权申请同步需求

背景：

- 手机端商机提报后，需要发起企业内部 OA 商机报备流程。
- 领导确认商机报备并归档后，OA 会生成商机报备流程号。
- 业务在项目授权申请流程发起前，仍允许在手机端修改需求设备类型等报备内容。
- OA 项目授权申请流程已存在，需要在流程发起前通过接口同步最新商机报备信息。

核心决策：

- 商机系统是需求设备类型等字段的主数据源。
- OA 商机报备归档保存审批快照，不作为最新设备需求来源。
- OA 项目授权申请流程发起前，传入商机报备流程号，由商机系统返回最新商机数据。
- 项目授权申请流程发起后，需求设备类型字段临时冻结。
- 到授权书创建审批 06 节点后，第一期只硬锁定需求设备类型字段。
- 投标供应商名称、预估采购金额、金额单位、预计投标截止时间纳入 OA 同步版本号。
- 管理员特殊修正硬锁定字段不需要单独 OA 审批，但必须保留高风险操作记录。
- OA 预填和回调接口通过企业内部统一网关对接，具体规范以 OA 标准接口文档为准。
- OA 表单中的需求设备类型字段第一期默认只读；若后续允许 OA 内编辑，必须回写商机系统并生成修订记录。

### 变更：用户端商机提报数据结构设计

背景：

- 用户需要通过前端系统提报数据。
- 提报渠道需要同时支持手机端和 PC 端。
- 后台管理人员需要查看和管理所有用户提报数据。

核心决策：

- 手机端和 PC 端都需要填写 Excel 商机池全部字段。
- 将字段拆分为用户需填写字段、管理员维护字典、系统自动字段。
- 手机端采用分步/分组表单、草稿保存、默认值和字典选择，提高完整填写效率。
- 管理端保留完整字段、筛选、编辑、补齐、追溯能力。
- 普通用户通过企业微信登录，可编辑自己的商机；领导或授权用户可查看、编辑白名单人员商机。
- 金额单位最终暂不确定，每个金额字段需要记录金额单位。
- 设备类型、授权品类由管理员维护，初始采用 Excel 现有值。
- 需要重复提报检测。
- 需要附件上传。
- 商机进度需要通过企业微信提醒用户持续跟进。

冲突处理：

- 兼容上一版设备事业群字段改造。
- 建议新增用户提报接口 `POST /api/opportunities/submissions`，与管理端商机创建/编辑分离。
- 金额字段不再强制固定为“万元”，改为金额 + 单位方式保存，避免旧系统“元”和 Excel“万元”的冲突继续扩大。

关联文档：

- `docs/requirements/2026-05-24-用户端商机提报数据结构设计.md`

### 变更：企业微信身份、我的商机与白名单权限

背景：

- 手机端需要实现商机提报和商机看板。
- 商机看板需要限制普通用户只能查看自己的商机。
- 领导需要通过白名单查看和编辑指定人员商机。
- 管理员需要查看和编辑全部商机。

核心决策：

- 企业微信 `wecomUserId` 是权限判断唯一依据，姓名只用于展示。
- 第一期手机端先使用沙箱模拟登录，预留真实企业微信 SSO 接入。
- 后续通过企业微信 API 自动同步用户、部门和标签。
- 新增用户板块，用于展示同步用户、配置角色、启用状态和白名单。
- 管理员可手动配置，也可根据企业微信部门或标签自动识别；手动配置可覆盖自动识别结果。
- 手机端只保留一个入口：`我的商机`。
- `我的商机` 范围由后端根据当前用户、白名单和管理员权限计算。
- 领导白名单按“领导/授权用户 -> 可查看人员列表”配置，第一期仅支持用户白名单。
- 白名单同时允许查看和编辑指定人员商机，编辑所有字段。
- 白名单配置页面仅管理员可用，领导不能自行配置自己的白名单。
- 历史 Excel 导入数据第一期标记为未归属，仅管理员可见。
- 离职/禁用用户不能登录，其历史商机保留；管理员和有白名单权限的领导仍可见。
- 所有商机编辑都必须生成字段级修订记录，普通用户、领导、管理员可在有权限的商机详情中查看。

影响：

- 商机表需要新增 `creatorUserId`、`submitterUserId`、`ownerUserId`、`visibilityStatus` 等企业微信归属字段。
- 需要新增用户、用户白名单、字段级修订记录相关模型和接口。
- `GET /api/opportunities` 不能只靠前端筛选，后端必须强制执行数据隔离。
- 手机端看板、列表和详情需要统一使用后端返回的可见数据范围。
