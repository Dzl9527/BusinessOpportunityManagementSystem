### 变更：用户端商机提报数据结构设计

背景：

- 用户需要通过前端系统提报数据。
- 提报渠道需要同时支持手机端和 PC 端。
- 后台管理人员需要查看和管理所有用户提报数据。

核心决策：

- 手机端和 PC 端都需要填写 Excel 商机池全部字段。
- 将字段拆分为用户需填写字段、管理员维护字典、系统自动字段。
- 手机端采用分步/分组表单、草稿保存、默认值和字典选择，提高完整填写效率。
- 管理端保留完整字段、筛选、编辑、补齐、追溯能力。
- 普通用户通过企业微信登录，可编辑自己的商机；领导或授权用户可查看、编辑白名单人员商机。
- 金额单位最终暂不确定，每个金额字段需要记录金额单位。
- 设备类型、授权品类由管理员维护，初始采用 Excel 现有值。
- 需要重复提报检测。
- 需要附件上传。
- 商机进度需要通过企业微信提醒用户持续跟进。

冲突处理：

- 兼容上一版设备事业群字段改造。
- 建议新增用户提报接口 `POST /api/opportunities/submissions`，与管理端商机创建/编辑分离。
- 金额字段不再强制固定为“万元”，改为金额 + 单位方式保存，避免旧系统“元”和 Excel“万元”的冲突继续扩大。

关联文档：

- `docs/requirements/2026-05-24-用户端商机提报数据结构设计.md`

### 变更：企业微信身份、我的商机与白名单权限

背景：

- 手机端需要实现商机提报和商机看板。
- 商机看板需要限制普通用户只能查看自己的商机。
- 领导需要通过白名单查看和编辑指定人员商机。
- 管理员需要查看和编辑全部商机。

核心决策：

- 企业微信 `wecomUserId` 是权限判断唯一依据，姓名只用于展示。
- 第一期手机端先使用沙箱模拟登录，预留真实企业微信 SSO 接入。
- 后续通过企业微信 API 自动同步用户、部门和标签。
- 新增用户板块，用于展示同步用户、配置角色、启用状态和白名单。
- 管理员可手动配置，也可根据企业微信部门或标签自动识别；手动配置可覆盖自动识别结果。
- 手机端只保留一个入口：`我的商机`。
- `我的商机` 范围由后端根据当前用户、白名单和管理员权限计算。
- 领导白名单按“领导/授权用户 -> 可查看人员列表”配置，第一期仅支持用户白名单。
- 白名单同时允许查看和编辑指定人员商机，编辑所有字段。
- 白名单配置页面仅管理员可用，领导不能自行配置自己的白名单。
- 历史 Excel 导入数据第一期标记为未归属，仅管理员可见。
- 离职/禁用用户不能登录，其历史商机保留；管理员和有白名单权限的领导仍可见。
- 所有商机编辑都必须生成字段级修订记录，普通用户、领导、管理员可在有权限的商机详情中查看。

影响：

- 商机表需要新增 `creatorUserId`、`submitterUserId`、`ownerUserId`、`visibilityStatus` 等企业微信归属字段。
- 需要新增用户、用户白名单、字段级修订记录相关模型和接口。
- `GET /api/opportunities` 不能只靠前端筛选，后端必须强制执行数据隔离。
- 手机端看板、列表和详情需要统一使用后端返回的可见数据范围。
