# 企业微信权限与移动端商机工程实现方案

日期：2026-05-24

## 1. 目标

本方案用于指导 Java 后端和 Vue 前端落地以下能力：

1. 手机端商机提报。
2. 手机端 `我的商机` 看板。
3. 基于企业微信 `wecomUserId` 的身份识别。
4. 普通用户、领导白名单、管理员三类权限隔离。
5. 企业微信组织架构自动同步。
6. 用户板块和白名单配置。
7. 字段级修订记录。

本方案是工程实现方案，配套文档：

- `docs/requirements/2026-05-24-用户端商机提报数据结构设计.md`
- `docs/requirements/2026-05-24-设备事业群商机字段改造需求.md`
- `docs/design/2026-05-24-设备事业群商机字段技术改造方案.md`
- `docs/design/2026-05-24-opportunity-field-migration.sql`

## 2. 总体架构

### 2.1 后端

技术栈：

- Java 17+
- Spring Boot 3.2.5
- Spring MVC
- Spring Data JPA
- H2 本地演示库，后续可迁移 MySQL/PostgreSQL

核心分层：

- `model`：JPA 实体。
- `repository`：数据访问。
- `service`：业务逻辑、权限逻辑、企业微信同步。
- `controller`：HTTP API。

### 2.2 前端

技术栈：

- Vue 3
- Vue Router
- Vite
- Axios

核心页面：

- `Login.vue`：沙箱登录和企业微信 SSO 入口。
- `Submit.vue`：手机端/PC 端商机提报。
- `Kanban.vue`：商机看板，手机端作为 `我的商机` 看板使用。
- `List.vue`：商机列表。
- `Users.vue`：用户板块，管理员维护角色和白名单。
- `OpportunityDrawer.vue`：商机详情、编辑、附件、修订记录。

## 3. 后端 Java 实现方案

### 3.1 Opportunity 实体扩展

文件：

`backend/src/main/java/com/boms/model/Opportunity.java`

新增企业微信归属字段：

```java
private String creatorUserId;
private String creatorName;
private String submitterUserId;
private String submitterName;
private String ownerUserId;
private String ownerName;
private String visibilityStatus; // ASSIGNED / UNASSIGNED
```

字段含义：

- `creatorUserId`：创建人企业微信 ID。
- `submitterUserId`：提报人企业微信 ID。
- `ownerUserId`：负责人企业微信 ID。
- `visibilityStatus = ASSIGNED`：已归属到企业微信用户。
- `visibilityStatus = UNASSIGNED`：历史导入或无法归属数据，仅管理员可见。

注意：

- 权限判断只使用 `wecomUserId` 字段。
- `creatorName`、`submitterName`、`ownerName` 只用于展示。
- 旧字段 `creator`、`submitter`、`owner` 可继续保留，兼容旧页面和历史数据。

### 3.2 SystemUser 实体

新增文件：

`backend/src/main/java/com/boms/model/SystemUser.java`

建议字段：

```java
private Long id;
private String wecomUserId;
private String name;
private String mobile;
private String email;
private String departmentId;
private String departmentName;
private String position;
private String role; // USER / LEADER / ADMIN
private Boolean canViewAll;
private Boolean enabled;
private String status; // ACTIVE / LEFT / DISABLED
private String adminSource; // MANUAL / DEPARTMENT / TAG
private String lastSyncedAt;
private String createdAt;
private String updatedAt;
```

规则：

- `wecomUserId` 唯一。
- `enabled = false` 的用户不能登录。
- `status = LEFT` 或 `DISABLED` 的用户不能登录。
- 管理员可手动配置，也可根据企业微信部门或标签自动识别。
- 手动配置可覆盖自动识别结果。

### 3.3 UserVisibilityRule 实体

```java
private Long id;

private Boolean canEdit;
```

规则：

### 3.4 OpportunityChangeLog 实体

新增文件：

`backend/src/main/java/com/boms/model/OpportunityChangeLog.java`

建议字段：

```java
private Long id;
private Long opportunityId;
private String editorUserId;
private String editorName;
private String editedAt;
private String fieldName;
private String fieldLabel;
private String oldValue;
private String newValue;
private String source; // MOBILE / PC / IMPORT / SYSTEM
```

规则：

- 每个字段变化生成一条记录。
- 普通用户、领导、管理员可查看自己有权限商机的修订记录。
- 领导编辑白名单人员商机时，必须记录 `permissionSource = WHITELIST`。

### 3.7 OpportunityPermissionService

新增文件：

`backend/src/main/java/com/boms/service/OpportunityPermissionService.java`

职责：

- 计算可见人员范围。
- 判断商机是否可见。
- 判断商机是否可编辑。
- 返回权限来源。

核心规则：

```text
管理员：
  可查看全部
  可编辑全部

普通用户：
  可查看/编辑 creatorUserId、submitterUserId、ownerUserId 等于自己的商机
  不可查看 UNASSIGNED

领导/授权用户：
  可查看/编辑自己的商机
  可查看/编辑白名单人员商机
  不可查看 UNASSIGNED

历史未归属：
  visibilityStatus = UNASSIGNED
  仅管理员可见
```

方法建议：

```java
boolean canView(SystemUser user, Opportunity opp);
boolean canEdit(SystemUser user, Opportunity opp);
String permissionSource(SystemUser user, Opportunity opp);
Set<String> getVisibleUserIds(SystemUser user);
Set<String> getEditableUserIds(SystemUser user);
List<Opportunity> filterVisible(SystemUser user, List<Opportunity> opportunities);
```

### 3.8 OpportunityService

新增或逐步抽离：

`backend/src/main/java/com/boms/service/OpportunityService.java`

职责：

- 创建商机。
- 更新商机。
- 查询商机。
- 重复检测。
- 附件关联。
- 企业微信提醒。
- 字段级修订记录生成。

关键逻辑：

1. 创建商机时补齐：

```text
creatorUserId
creatorName
submitterUserId
submitterName
ownerUserId
ownerName
visibilityStatus = ASSIGNED
```

2. Excel 导入时：

```text
visibilityStatus = UNASSIGNED
creatorUserId = null
submitterUserId = null
ownerUserId = null
```

3. 更新商机前：

```text
permissionService.canEdit(currentUser, opportunity)
```

4. 更新商机后：

```text
比较字段变化
写入 OpportunityChangeLog
写入 ActivityLog 摘要
```

## 4. Controller API 方案

### 4.1 用户接口

新增：

`backend/src/main/java/com/boms/controller/UserController.java`

接口：

```text
GET /api/users
GET /api/users/me
POST /api/users/sync-wecom
PUT /api/users/{wecomUserId}/role
PUT /api/users/{wecomUserId}/enabled
GET /api/users/{wecomUserId}/visibility-rules
PUT /api/users/{wecomUserId}/visibility-rules
```

权限：

- `GET /api/users/me` 当前登录用户可用。
- 用户列表、同步、角色、白名单配置仅管理员可用。

### 4.2 商机接口

现有：

```text
GET /api/opportunities
GET /api/opportunities/{id}
POST /api/opportunities
PUT /api/opportunities/{id}
DELETE /api/opportunities/{id}
```

调整：

- `GET /api/opportunities` 默认按当前用户权限过滤。
- 管理员可通过参数或角色查看全部。
- `GET /api/opportunities/{id}` 必须校验 `canView`。
- `PUT /api/opportunities/{id}` 必须校验 `canEdit`。
- `DELETE /api/opportunities/{id}` 第一阶段建议仅管理员可用。

新增：

```text
GET /api/opportunities/mine
GET /api/opportunities/{id}/change-logs
```

### 4.3 企业微信接口

现有：

```text
GET /api/wecom/auth
GET /api/wecom/contacts
GET /api/wecom/jsapi-signature
POST /api/wecom/push-test
```

调整：

- `GET /api/wecom/auth` 登录成功后应返回本地 `SystemUser` 角色、启用状态、权限信息。
- 禁用、离职用户不能登录。
- 沙箱模式返回模拟用户。

## 5. 企业微信同步方案

### 5.1 第一期沙箱

使用 `WeComService.getContactList()` 返回模拟用户。

同步到 `system_users`：

- `zhang_jingli`
- `li_zhuguan`
- `wang_xiaoshou`

可预置一个管理员用户，例如：

```text
zhang_jingli role=ADMIN canViewAll=true
```

### 5.2 后续真实同步

通过企业微信 API：

- 获取 access token。
- 获取部门列表。
- 获取部门成员。
- 获取成员详情。
- 获取标签成员，用于自动识别管理员。

同步策略：

- 以 `wecomUserId` upsert。
- 企业微信改名后更新 `name`。
- 企业微信禁用/离职后更新 `status`。
- 不删除用户，保留历史商机归属。
- 同步失败时保留上一次成功数据。

## 6. 前端 Vue 实现方案

### 6.1 路由

修改：

`frontend/src/router/index.js`


手机端导航：

- 用户板块仅管理员显示。

### 6.2 Store

修改：

`frontend/src/store/index.js`

新增方法：

```js
fetchCurrentUser()
fetchUsers()

updateUserRole(userId, payload)
updateUserEnabled(userId, enabled)
fetchVisibilityRules(userId)
saveVisibilityRules(userId, visibleUserIds)
```

注意：

- 当前用户身份应包含 `userId`、`name`、`role`、`canViewAll`、`enabled`。

### 6.3 Submit.vue

职责：

- 分步填写 Excel 商机池字段。
- 支持重复检测。
- 支持附件记录。
- 提交到 `POST /api/opportunities/submissions`。

提交时：

- 前端传当前登录用户信息。
- 后端以当前用户为准补齐企业微信归属字段。
- 前端不能自行决定可见权限。

### 6.4 Kanban.vue / 我的商机

职责：

- 手机端作为 `我的商机` 看板。
- 数据来源使用 `GET /api/opportunities/mine` 或 `GET /api/opportunities?mine=true`。
- 展示当前用户可见范围内商机。

规则：

- 不在前端手动按姓名筛选。
- 拖拽阶段时调用后端更新接口，由后端判断编辑权限。
- 无权限时展示后端错误提示。

### 6.5 Users.vue

新增文件：

`frontend/src/views/Users.vue`

管理员功能：

- 用户列表。
- 企业微信同步按钮。
- 角色配置。
- 启用/禁用。
- 白名单配置。

白名单交互：

- 选择一个领导/授权用户。
- 勾选可查看/编辑人员。
- 保存到 `PUT /api/users/{wecomUserId}/visibility-rules`。

### 6.6 OpportunityDrawer.vue

新增：

- 修订记录 Tab 或分组。
- 展示字段名、修改前、修改后、修改人、修改时间、权限来源。

规则：

- 只展示当前用户有权限商机的修订记录。
- 修订记录由后端返回，前端不自行过滤。

短期：

- JPA `ddl-auto:update` 可自动建表。
- Excel 导入脚本应把历史数据标记为 `UNASSIGNED`。

### 7.2 正式数据库

`docs/design/2026-05-24-opportunity-field-migration.sql`

- 商机归属字段。

## 10. 风险与约束

1. 不能使用姓名做权限判断，必须使用 `wecomUserId`。
2. 白名单允许编辑所有字段，修订记录必须完整。
3. 历史 Excel 数据第一期未归属，普通用户可能看不到历史商机。
4. 当前 H2 内存库不适合生产，需要后续切换持久化数据库。
5. 企业微信真实同步依赖 CorpID、通讯录 Secret、应用 Secret、可信域名和回调地址。
6. 前端隐藏按钮不是权限控制，后端必须兜底。
7. 企业微信组织架构变化不能删除历史用户，否则历史商机归属会丢失。
