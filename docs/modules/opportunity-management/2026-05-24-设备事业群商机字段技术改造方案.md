# 设备事业群商机字段技术改造方案

日期：2026-05-24

## 1. 当前代码现状

### 后端

- `backend/src/main/java/com/boms/model/Opportunity.java`：商机实体，字段偏通用 CRM。
- `backend/src/main/java/com/boms/controller/OpportunityController.java`：包含查询、创建、更新、删除、指标、图表、任务、活动全部逻辑。
- `backend/src/main/java/com/boms/repository/OpportunityRepository.java`：仅继承 `JpaRepository`。
- 当前没有 DTO、没有独立 `OpportunityService`、没有权限服务、没有正式 SQL migration。

### 前端

- `frontend/src/views/List.vue`：商机列表、筛选、新增/编辑表单。
- `frontend/src/views/Kanban.vue`：按 CRM 阶段看板拖拽。
- `frontend/src/views/Submit.vue`：移动端/PC 共用商机提报页面。
- `frontend/src/components/OpportunityDrawer.vue`：详情、任务、跟进日志。
- `frontend/src/views/Dashboard.vue`：指标与图表。
- `frontend/src/store/index.js`：接口调用和状态管理。

## 2. 推荐改造策略

采用兼容式扩展，不直接推翻旧模型。

原因：

- 当前前端和后端大量直接使用 `Opportunity` 字段。
- 历史数据字段少，新增字段可为空。
- Excel 金额单位与现有前端“元”冲突，需要过渡。

- `deviceTypes`、`authorizedCategories` 在 API 层建议使用数组；数据库短期可用逗号分隔字符串，长期建议抽成字典表和关联表。
- 商机进度提醒建议使用 `businessProgressStatus`，旧 `stage` 继续兼容 CRM 看板。

建议新增实体：

- `OpportunityAttachment`：商机附件。
- `OpportunityDictionaryItem`：设备类型、授权品类、行业、采购形式、省区等字典。
- `OpportunityReminder`：企业微信提醒记录和提醒状态。
- `OpportunityDuplicateMark`：重复商机提示/合并记录。
- `OpportunityChangeLog`：字段变更记录。
- `SystemUser`：企业微信同步用户和本地角色配置。
- `UserVisibilityRule`：用户白名单权限配置。

### 企业微信身份字段说明

- 权限判断必须使用企业微信 `wecomUserId`，不能使用姓名、`owner` 文本或前端筛选结果。
- `creatorUserId`、`submitterUserId`、`ownerUserId` 用于判断当前用户自己的商机和白名单人员商机。
- `creatorName`、`submitterName`、`ownerName` 仅用于展示，可跟随用户表最新姓名更新。
- 历史 Excel 导入数据第一期无法匹配企业微信用户时，设置 `visibilityStatus = "UNASSIGNED"`，仅管理员可见。
- 用户改名不影响权限判断，因为权限基于 `wecomUserId`。

## 5. Service 改造

新增文件：

`backend/src/main/java/com/boms/service/OpportunityService.java`
`backend/src/main/java/com/boms/service/OpportunityPermissionService.java`
`backend/src/main/java/com/boms/service/UserDirectoryService.java`

职责：

- 创建商机：补齐默认任务、默认活动日志、系统自动提报日期。
- 更新商机：比较阶段、赢率、关键业务字段变化并写活动日志。
- 字段校验：项目名称、金额、赢率枚举、采购形式枚举。
- 金额兼容：根据金额单位换算统计金额，不再默认所有金额都是万元。
- 查询筛选：集中处理多条件筛选。
- 用户提报权限校验：普通用户只能查看和编辑自己的商机；领导或授权用户可查看和编辑白名单人员商机；管理员可查看和编辑全部商机。
- 数据隔离：普通用户和领导默认不返回 `UNASSIGNED` 历史数据。
- 字段级审计：更新商机时比较字段变化并写入 `OpportunityChangeLog`。
- 用户目录：同步企业微信组织架构用户、维护本地角色和启用状态。
- 白名单权限：维护“领导/授权用户 -> 可查看人员列表”，第一期查看和编辑范围一致。
- 重复提报检测：提交前返回疑似重复商机。
- 附件关联：保存商机附件元数据。
- 企业微信提醒：根据进度、投标截止、交付时间、周更新等规则创建提醒。

核心逻辑建议：

```java
private static final Map<String, Integer> WIN_RATE_VALUES = Map.of(
    "10%-没有把握", 10,
    "30%-把握很小", 30,
    "50%-可以参与", 50,
    "70%-赢面很大", 70,
    "100%-肯定中标", 100
);

private void normalizeOpportunity(Opportunity opp) {
    if (opp.getWinRateLabel() != null && WIN_RATE_VALUES.containsKey(opp.getWinRateLabel())) {
        opp.setProbability(WIN_RATE_VALUES.get(opp.getWinRateLabel()));
    }
    if (opp.getEstimatedPurchaseAmount() != null) {
        double amount = opp.getEstimatedPurchaseAmount();
        if ("万元".equals(opp.getEstimatedPurchaseAmountUnit())) {
            amount = amount * 10000;
        }
        opp.setValue(amount);
    }
}
```

权限过滤建议：

```java
public boolean canView(Opportunity opp, SystemUser currentUser) {
    if (currentUser.isAdmin() || currentUser.getCanViewAll()) {
        return true;
    }
    if ("UNASSIGNED".equals(opp.getVisibilityStatus())) {
        return false;
    }
    Set<String> allowedUserIds = visibilityRuleRepository.findVisibleUserIds(currentUser.getWecomUserId());
    allowedUserIds.add(currentUser.getWecomUserId());
    return allowedUserIds.contains(opp.getCreatorUserId())
        || allowedUserIds.contains(opp.getSubmitterUserId())
        || allowedUserIds.contains(opp.getOwnerUserId());
}
```

## 11. 风险点

1. 金额单位风险：Excel 字段名是万元，但样例中存在 `50000`、`100000` 等值，可能实际混用了元和万元。
2. 字段语义风险：Excel 末尾 `数字`、`数字 2`、`日期`、`文本`、`单选`、`日期 2` 没有业务名称。
3. 阶段缺失风险：Excel 说明要求每周更新项目阶段，但副本中没有明确“项目阶段”字段。
4. 赢率联动风险：旧系统拖拽阶段会自动改赢率，可能覆盖业务枚举赢率。
5. 角色冲突风险：`owner`、`销售`、`提报人`、`创建人` 不是同一概念。
6. 数据类型风险：当前系统日期均为字符串，后续统计和排序会受格式影响。
7. H2 内存库风险：当前数据不持久化，不适合承载 1900 行历史 Excel 数据。
8. Controller 膨胀风险：继续把业务逻辑放在 Controller 会使后续维护困难。
9. 手机端全字段提报风险：字段多，需要分步、草稿和默认值支持。
10. 权限风险：必须以后端企业微信 `wecomUserId` 做强制过滤，不能只依赖前端筛选、姓名或 `owner` 文本字段。
11. 附件风险：文件上传需要限制大小、类型、权限和存储策略。
12. 提醒风险：企业微信提醒需要防止重复轰炸，提醒规则需可配置。
13. 重复检测风险：相似匹配无法 100% 准确，建议提示不拦截。
14. 白名单编辑风险：领导可编辑白名单人员所有字段，必须依赖字段级修订记录保证可追责。
15. 企业微信同步风险：组织架构同步失败时，应保留上一次可用用户数据并提示管理员同步状态。
16. 历史数据归属风险：Excel 导入数据第一期未归属，普通用户可能看不到历史商机，需要后续归属映射能力。

## 12. 实施顺序

1. 新增用户、白名单、修订记录表和商机企业微信归属字段。
2. 新增 Entity、Repository、DTO 和权限 Service。
3. Controller 改为调用 Service，并在查询/编辑时统一执行权限校验。
4. 前端新增用户板块、我的商机入口、修订记录展示。
5. 前端列表/表单/详情增加设备事业群字段。
6. 仪表盘增加专项统计。
7. 编写 Excel 导入脚本或接口，历史数据第一期标记为 `UNASSIGNED`。
8. 回归验证旧商机创建、编辑、看板拖拽、仪表盘、手机端我的商机和白名单权限。
