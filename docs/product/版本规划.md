# 版本规划

本文档用于记录项目的版本节奏、近期目标和发布边界。它回答的问题是：下一步先做什么、做到什么程度可以发布、哪些内容暂时不做。

## 分支约定

- `main`：稳定分支，只保存已经验证过、可以随时启动或发布的代码。
- `dev`：日常开发集成分支，新功能和修复先合并到这里验证。
- `feature/xxx`：新功能临时分支，例如 `feature/mobile-submit`。
- `fix/xxx`：普通 Bug 修复临时分支，例如 `fix/login-error`。
- `hotfix/xxx`：线上紧急修复临时分支，从 `main` 拉出，修复后合回 `main` 和 `dev`。

当前项目规模不大，第一阶段只强制维护 `main` 和 `dev` 两个长期分支即可。

## 版本号规则

采用 `主版本.次版本.修订版本`：

- 主版本：业务模型或权限体系出现重大变化。
- 次版本：新增一个完整业务能力，例如企业微信真实登录、附件上传、提醒。
- 修订版本：Bug 修复、小范围体验优化、文档补充。

示例：

- `0.1.0`：内部可运行基线。
- `0.2.0`：进度提醒和管理端配置闭环。
- `0.2.1`：修复手机端表单或权限边界问题。

## 已发布：0.1.0

目标：完成内部演示和本地验证闭环。

已具备：

- PC 商机列表和详情查看。
- 手机端商机提报入口。
- 手机端 `我的商机` 看板。
- 企业微信沙箱模拟登录。
- 用户管理和用户白名单配置。
- 管理员查看全部商机。
- 白名单范围内查看和编辑商机。
- 商机字段级修订记录。
- Excel 历史商机导入。
- 历史未归属商机默认仅管理员可见。
- 本地需求、设计、变更记录文档库。

未覆盖：

- 真实企业微信 SSO。
- 企业微信通讯录、部门、标签自动同步。
- 生产级数据库和正式迁移脚本。
- 附件上传。
- 重复提报检测。
- 企业微信提醒。
- 自动化测试和 CI。

## 已发布：0.2.0 (2026-05-29)

目标：增加进度跟进通知体系，从“本地演示系统”向“试点运行系统”推进。

实际交付范围：

- **企业微信机器人商机进度提醒**（原定于 0.3.0 候选，现提前在该版本完成闭环交付）：包含 7 个触发场景的定时扫描与消息直达，支持后台参数持久化配置与管理员一键联调。
- **系统设置界面重构优化**：移除顶部冗余的 4 个全局指标卡片，将权限统计收纳到「组织权限管理」标签页内。
- 设置页新增提醒参数配置、立即执行提醒扫描和通讯录同步联调入口。
- 手机端主导航最终调整为 `工作台`、`商机提报`、`商机列表`、`商机看板`、`用户中心`。
- 用户中心支持登录态展示、权限说明、主题切换和退出登录。

发布验收口径：

- 后端编译通过，前端构建通过。
- 进度提醒 7 个触发场景可通过后台联调入口验证。
- 普通用户主导航不再暴露系统设置入口。
- 发布记录、需求变更记录和相关产品/需求文档同步更新。

## 近期目标：0.2.1

目标：补齐版本治理和本地交付可复现性。

候选范围：

- 统一 `CHANGELOG.md`、`docs/product/版本规划.md`、后端 `pom.xml` 和前端 `package.json` 的版本口径。
- 修正本地启动文档，避免依赖未入库的本机 Maven/JDK 路径。
- 将可复用脚本归档到 `tools/`，临时实验脚本归档到 `scratch/` 并避免继续扩大。
- 补充最小 CI，覆盖后端编译和前端构建。
- 更新 `docs/README.md` 文档索引。

## 后续目标：0.3.0

目标：补齐商机提报后的协同和运营能力。

候选范围：

- 接入真实企业微信 SSO，完成 `wecomUserId` 登录闭环。
- 调用企业微信 API 同步用户、部门和标签。
- 将 H2 内存库替换为可持久化数据库。
- 梳理数据库迁移脚本和初始化数据脚本。
- 后端增加权限过滤和编辑审计的自动化测试。
- 附件上传和预览。
- 重复提报检测。
- 商机状态流转配置。
- 字典项后台维护增强。
- 看板统计、筛选和导出。
- 移动端表单草稿。

## 暂缓事项

- 复杂的多级审批流。
- 领导自助维护白名单。
- 跨企业、多租户隔离。
- 复杂 BI 报表。

这些能力等一期权限、提报、看板闭环稳定后再评估。
