# V2.0 整体架构演进与安全改造方案

**日期:** 2026-06-14

## 背景
随着 BOMS（商机管理系统）的数据规模不断扩大，原有的架构（H2 内存数据库、无安全鉴权体系的裸接口透传）已经无法满足后续的性能、高可用及安全性要求。经共同探讨，启动了“BOMS V2.0 宏大架构重构计划”。

## Phase 1: 存储层基建升级与 Docker 化
为了实现数据持久化和一键拉起部署，同时兼顾本地开发体验，进行了如下改造：
1. **多环境配置 (Spring Profiles)**
   - `application.yml` 保留 H2 数据库作为 `dev` (默认) 环境，无需安装外部服务即可进行本地开发。
   - 新增 `application-prod.yml` 连接 MySQL 8.0 数据库作为生产环境配置。
2. **Docker 化编排**
   - 新增后端的多阶段构建 `Dockerfile` (基于 `eclipse-temurin:17`)。
   - 新增前端的 Nginx 静态部署 `Dockerfile`。
   - 新增 `docker-compose.yml` 统一编排 MySQL、Redis、后端、前端四个容器服务，并注入环境变量 `SPRING_PROFILES_ACTIVE=prod`。

## Phase 2: 安全体系与接口重构
为了消除基于 URL 参数透传 `userId` 的安全隐患，进行了如下改造：
1. **引入 Spring Security & JWT**
   - 依赖项加入 `spring-boot-starter-security` 和 `java-jwt`。
   - 增加 `JwtTokenProvider` 签发 Token；增加 `JwtAuthenticationFilter` 对非授权请求进行拦截验证。
   - 更新企微登录接口 `WeComController.authenticate` 下发真实的 JWT。
2. **前后端接口解耦**
   - 前端：移除了所有的 `currentUserParams` 和 `adminParams`，统一由 Axios 的 Request 拦截器自动在 Header 中注入 `Authorization: Bearer <Token>`。
   - 后端：删除了全盘 Controller 方法上的 `@RequestParam String userId`，改为通过自定义的 `SecurityUtils.getCurrentUserId()` 提取上下文中的鉴权身份。

## Phase 3: Redis 缓存层引入与高可用改造
为解决高并发提报场景下大盘指标接口查询慢、企业微信通讯录同步慢的瓶颈，我们引入了缓存层：
1. **基础设施**：`docker-compose.yml` 引入 `redis:7.0-alpine`，`application-prod.yml` 配置启用 Redis Cache；本地保留 `SimpleCache` (ConcurrentHashMap) 维持无痛开发体验。
2. **应用层加速**：
   - 使用 Spring Cache (`@Cacheable`) 对 `OpportunityController` 中的 4 个看版图表大盘数据进行缓存。
   - 缓存的 `key` 使用 SpEL 表达式绑定了当前操作者的鉴权身份：`#userId != null ? #userId : T(com.boms.security.SecurityUtils).getCurrentUserId()`。
   - 对 `WeComService.getContactList` 增加全局缓存。
3. **缓存失效策略**：设计为最终一致性方案，统一通过 `CacheConfig` 配置全局的 5 分钟 TTL（自动过期时间），避免在高频更新场景下产生缓存击穿或缓存雪崩。

## Phase 4: 前端架构演进 (Pinia & TypeScript)
为适应日益庞大的前端组件与数据状态，进行了大规模前端重构：
1. **TypeScript 渐进式引入**：将 Vite 及 Vue 模板链升级为 TypeScript 生态，增加 `tsconfig.json` 并全局采用 `<script setup lang="ts">`。为防重构步子过大引发雪崩，采用 `noImplicitAny: false` 的柔性编译策略。
2. **状态层模块化解耦 (Pinia)**：废弃了原有高达 400 行的 `reactive` 巨无霸 `store/index.js`，按领域模型划分为：
   - `useAppStore`: 全局 UI (Toast, Theme)
   - `useAuthStore`: 用户鉴权与 Token
   - `useOppStore`: 商机列表、字典配置与操作接口
   - `useMetricsStore`: 看板统计数据
   - `useUserStore`: 企业微信通讯录与用户同步
3. **副作用与钩子分离**：Axios 的 Token 拦截器从 Store 中剥离，转移至独立于 Vue 实例化的 `main.ts` 初始化生命周期中。
