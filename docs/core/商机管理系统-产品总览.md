# 商机管理系统 - 产品总览

更新时间：2026-05-26

## 产品定位

当前项目是一个面向销售团队和设备事业群业务人员的商机管理系统，已有能力包括商机录入、列表检索、看板阶段流转、商机详情、待办任务、跟进日志、工作台统计、企业微信登录与通知。后续移动端能力以企业微信身份为核心，支持商机提报、工作台、商机看板、商机列表、用户中心、权限隔离和字段级修订追溯。

## 当前系统能力

后端：

- Spring Boot 3.2.5
- JPA + H2 内存数据库
- 核心实体：`Opportunity`、`TaskItem`、`ActivityLog`
- 核心接口：`/api/opportunities`

前端：

- Vue + Vite
- 页面：Dashboard、List、Kanban、Submit、UserCenter、Settings、Login、Users
- 核心组件：`OpportunityDrawer`

## 当前手机端产品口径

2026-05-26 进一步确认手机端信息架构，第一期手机端一级导航统一为：

- 工作台
- 商机提报
- 商机列表
- 商机看板
- 用户中心

说明：

- `工作台` 是原“仪表盘”的业务首页命名，负责摘要、提醒和快捷入口。
- `用户中心` 承担登录状态展示、个人信息、权限说明和退出登录。
- `系统设置` 作为管理员专属入口保留，不作为普通用户一级导航暴露。
- `商机提报`、`商机列表`、`商机看板` 按录入、检索、推进的顺序承接核心业务流程。

## 当前商机核心模型

当前 `Opportunity` 偏通用 CRM 模型：

- 商机名称：`name`
- 客户公司：`company`
- 阶段：`stage`
- 金额：`value`
- 赢率：`probability`
- 预计结单日期：`closeDate`
- 联系人：`contactName`、`contactPhone`、`contactEmail`
- 来源：`source`
- 优先级：`priority`
- 负责人：`owner`
- 描述：`description`

## 新业务方向

设备事业群 Excel 表明，业务要从通用销售商机模型升级为设备事业群专项商机池，重点管理：

- 提报人、政企市场部经理、提报省区、供货省区
- 采购单位、行业、项目名称、供应商
- 设备类型、品类型号、数量、金额
- 参数前置、唯一授权、授权品类
- 预计交付、投标截止、中标结果、采购形式
- 报备成功状态、销售部门、销售、省总、A4/A3 业务经理
- 提醒编辑时间、最后编辑时间

## 用户提报方向

2026-05-24 新增用户端提报设计：系统需要支持手机端和 PC 端双渠道提报。经业务确认，手机端和 PC 端都需要支持填写 Excel 商机池全部字段。系统通过分步表单、草稿保存、默认值、字典选择、重复检测、附件上传和企业微信提醒提高填写与跟进效率。

用户端重点保证完整提报与移动端高频闭环：

- Excel 商机池字段完整覆盖
- 普通用户通过企业微信登录，权限判断以企业微信 `wecomUserId` 为准
- 手机端提供 `工作台`、`商机提报`、`商机列表`、`商机看板`、`用户中心`
- 普通用户可查看和编辑自己的商机
- 领导或被授权用户可查看、编辑白名单人员商机
- 管理员可查看、编辑全部商机
- 历史未归属商机仅管理员可见
- 金额字段记录金额和单位，单位暂不强制固定为万元
- 设备类型、授权品类等选项由管理员维护，初始采用 Excel 现有值
- 提交时进行重复商机检测
- 支持附件上传
- 按商机进度通过企业微信提醒用户持续跟进
- 所有编辑需要生成字段级修订记录，普通用户、领导和管理员可在有权限的商机详情中查看
- 用户中心支持登录态展示和退出登录
- 系统设置面向管理员提供企业微信配置、通知联调、数据管理和演示环境维护

补充说明：

- 商机详情页虽然不是一级导航，但属于看板、列表和提报后的共用落点，应纳入手机端核心能力。
- 管理端能力继续承载完整字段查看、筛选、补齐、编辑、统计和追溯，但在手机端不应作为普通用户一级主入口。

## OA 流程集成方向

2026-05-25 新增 OA 商机报备与项目授权申请同步设计。系统需要支持手机端提报商机后发起 OA 商机报备流程，领导确认并归档后，由 OA 回写商机报备流程号。后续用户发起项目授权申请流程前，OA 可通过商机报备流程号调用商机系统接口，实时获取最新商机报备信息和最新需求设备类型。

核心口径：

- 商机系统是设备需求类型的主数据源。
- OA 商机报备归档保存的是审批快照，不作为最新设备需求来源。
- 业务在项目授权申请流程发起前，可以在手机端修改自己有权限商机的需求设备类型。
- 项目授权申请流程发起后，需求设备类型字段进入临时冻结。
- 到授权书创建审批 06 节点后，需求设备类型字段进入硬锁定。
- 投标供应商名称、预估采购金额、金额单位、预计投标截止时间纳入 OA 同步版本号。
- OA 项目授权申请表单中的需求设备类型字段第一期默认只读；如后续允许 OA 内编辑，必须回写商机系统并生成修订记录。
- OA 预填和回调接口通过企业内部统一网关对接，具体规范以 OA 标准接口文档为准。

## 用户与权限方向

新增用户板块，承接企业微信组织架构同步和权限配置。

用户来源：

- 第一期手机端先使用沙箱模拟登录。
- 后续系统调用企业微信 API 自动同步用户、部门和标签。
- `wecomUserId` 是权限判断唯一依据，姓名只用于展示。
- 用户改名后，展示姓名跟随用户表最新姓名。

权限配置：

- 管理员可手动配置，也可根据企业微信部门或标签自动识别。
- 白名单配置页面仅管理员可用。
- 第一期白名单采用“领导/授权用户 -> 可查看人员列表”。
- 白名单同时授予查看和编辑权限，第一期不拆分“可看不可改”。
- 后续可扩展部门授权、权限组和查看/编辑范围拆分。

修订追溯：

- 所有字段编辑记录修改人、修改时间、字段名、修改前、修改后、修改来源和权限来源。
- 领导编辑白名单人员商机时，必须可追责到实际修改人和权限来源。
- 离职/禁用用户不能登录，其历史商机仍保留，管理员和有白名单权限的领导可见。

## 文档治理规则

后续新增需求必须先检查：

- 是否新增/改变商机字段
- 是否影响列表筛选、看板阶段、仪表盘指标
- 是否改变金额单位
- 是否改变赢率/阶段含义
- 是否新增审批、授权、报备或提醒流程
- 是否影响 OA 商机报备、项目授权申请、设备需求锁定或流程号关联
- 是否影响历史数据兼容
- 是否影响企业微信身份、用户角色、白名单、商机可见范围或字段级修订记录
