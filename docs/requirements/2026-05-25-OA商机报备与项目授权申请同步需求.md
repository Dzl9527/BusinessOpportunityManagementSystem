# OA商机报备与项目授权申请同步需求

日期：2026-05-25

## 1. 背景

当前系统已经支持手机端商机提报、我的商机看板、企业微信身份识别、用户白名单权限和字段级修订记录。业务下一步需要将手机端商机提报与企业内部 OA 审批流程打通。

现有业务中已经存在项目授权 OA 流程（为兼容性，系统底层接口及字段仍使用 `bidDocumentFlow` / 投标文件制作 相关命名）。用户在手机端填写完整商机信息后，需要先发起商机报备 OA 流程，由领导确认并归档。后续用户在申请项目授权申请流程前，OA 需要根据商机报备流程号获取商机系统中的最新商机报备信息，尤其是最新的需求设备类型。

业务允许用户在开标前修改自己提报的商机报备内容，包含需求设备类型。此类修改在项目授权申请流程发起前不需要二次审批。但项目授权申请流程发起后，第一期只对需求设备类型字段进行临时冻结；到授权书创建审批 06 节点后，需求设备类型字段进入硬锁定，不再允许普通业务修改。

## 2. 目标

1. 手机端提报商机后，可发起 OA 商机报备流程。
2. OA 商机报备流程归档后，将 OA 流程号回写到商机系统。
3. 业务在项目授权申请流程发起前，可以在手机端修改自己有权限的商机报备内容。
4. OA 项目授权申请流程发起前，可以通过商机报备 OA 流程号调用商机系统接口，获取最新商机报备信息。
5. 项目授权申请流程发起后，需求设备类型字段进入临时冻结状态。
6. 到授权书创建审批 06 节点后，需求设备类型字段进入硬锁定状态。
7. 所有设备需求字段变更、锁定、解锁和 OA 同步动作都必须可追溯。

## 3. 非目标

第一期暂不实现：

- 替换现有 OA 项目授权申请流程。
- 在 OA 内设计完整项目授权申请表单。
- 在 OA 内强制用户修改设备需求字段。
- 复杂多级变更审批。
- 与最终授权书文件内容做自动文本比对。

## 4. 术语

| 术语 | 说明 |
|---|---|
| 商机系统 | 当前项目系统，保存商机主数据、权限、修订记录和 OA 关联信息 |
| OA 商机报备流程 | 用户提报商机后发起的内部 OA 审批流程，由领导确认后归档 |
| OA 项目授权申请流程 | 企业内部已有流程，用于申请项目授权（对应系统底层的 `bidDocumentFlow` 字段） |
| 商机报备流程号 | OA 商机报备流程归档后生成的流程编号，作为 OA 与商机系统关联键 |
| 需求设备类型字段 | `deviceTypes`，第一期项目授权流程发起后和 06 节点后的锁定对象 |
| 版本追踪字段 | 影响 OA 项目授权申请预填准确性的字段，变更时需要递增 `deviceRequirementVersion` |
| 最新主数据 | 商机系统中当前最新的商机字段值 |
| OA 快照 | OA 流程发起或归档时保存的一份当时字段值 |
| 临时冻结 | 流程进行中暂不允许业务在商机系统修改设备需求字段 |
| 硬锁定 | 进入关键审批节点后，不再允许普通业务修改设备需求字段 |

## 5. 核心原则

### 5.1 商机系统是设备需求主数据源

需求设备类型等字段以商机系统当前数据为准。OA 已归档流程保存的是历史审批快照，不作为最新设备需求的数据源。

### 5.2 OA 通过流程号回查最新数据

OA 项目授权申请流程发起前，如果只持有商机报备流程号，也必须通过商机系统接口找到对应商机，再返回最新设备需求信息。

### 5.3 OA 表单默认展示同步值，不直接改主数据

项目授权申请 OA 表单中的设备需求字段第一期默认只读。如果业务后续希望允许 OA 内编辑，可由 OA 配置成可编辑，但编辑后的值必须回写商机系统并生成修订记录，否则不视为有效主数据变更。

### 5.4 流程发起后冻结，关键节点后硬锁定

项目授权申请流程发起后，需求设备类型字段进入临时冻结。流程撤回、驳回或作废后必须解冻。到授权书创建审批 06 节点后，需求设备类型字段进入硬锁定。

### 5.5 私下修改不进入闭环

业务人员私下联系授权管理人员调整最终需求设备类型，不属于系统认可的正式变更。正式变更必须通过商机系统或可回写商机系统的 OA 节点完成，并保留修订记录。

## 6. 用户角色

| 角色 | 主要动作 |
|---|---|
| 业务提报人 | 手机端提报商机、修改自己商机、发起 OA 商机报备、发起项目授权申请 |
| 领导审批人 | 在 OA 中确认商机报备信息 |
| 授权管理人员 | 根据 OA 项目授权申请流程接收需求并进行商务授权处理 |
| 管理员 | 查看全部商机、处理异常、配置用户权限、查看修订和同步记录 |
| OA 系统 | 发起流程、归档流程、调用商机系统接口、回调流程状态 |
| 商机系统 | 保存主数据、校验权限、返回最新数据、记录修订和锁定状态 |

## 7. 业务流程

### 7.1 商机提报与商机报备流程

1. 用户通过企业微信身份登录手机端。
2. 用户填写完整商机信息。
3. 商机系统保存商机主数据，生成 `opportunityId`。
4. 用户发起 OA 商机报备流程。
5. 商机系统向 OA 传递商机报备表单所需字段。
6. OA 保存发起时的商机报备快照。
7. 领导在 OA 中确认商机报备信息。
8. OA 商机报备流程归档。
9. OA 将商机报备流程号回写商机系统。
10. 商机系统保存 `reportFlowNo`、归档时间、归档状态。

### 7.2 项目授权申请前同步

1. 用户准备发起 OA 项目授权申请流程。
2. OA 在流程发起前调用商机系统接口。
3. OA 传入商机报备流程号 `reportFlowNo`。
4. 商机系统根据 `reportFlowNo` 查找对应商机。
5. 商机系统返回当前最新商机报备信息。
6. OA 将返回字段填入项目授权申请表单。
7. OA 保存本次项目授权申请发起快照。
8. OA 通知商机系统项目授权申请流程已发起。
9. 商机系统将设备需求字段设置为临时冻结。

### 7.3 项目授权流程中需求设备类型锁定

1. 项目授权申请流程发起后，业务不能在手机端继续修改需求设备类型字段。
2. 如果流程撤回、驳回或作废，OA 回调商机系统。
3. 商机系统解除临时冻结。
4. 如果流程流转到授权书创建审批 06 节点，OA 回调商机系统。
5. 商机系统将需求设备类型字段设置为硬锁定。
6. 硬锁定后普通业务不能修改需求设备类型字段。
7. 管理员如需特殊修正，不需要单独 OA 审批，但必须走管理端操作并生成强审计记录。

## 8. 状态设计

### 8.1 商机报备 OA 状态

| 状态 | 说明 |
|---|---|
| `NOT_STARTED` | 未发起 OA 商机报备 |
| `IN_PROGRESS` | OA 商机报备审批中 |
| `ARCHIVED` | OA 商机报备已归档 |
| `REJECTED` | OA 商机报备被驳回 |
| `CANCELED` | OA 商机报备已撤回或作废 |

### 8.2 需求设备类型锁定状态

| 状态 | 说明 | 是否允许业务修改 |
|---|---|---|
| `UNLOCKED` | 需求设备类型未锁定，项目授权申请流程尚未发起或已解冻 | 允许修改需求设备类型 |
| `SOFT_LOCKED` | 项目授权申请流程已发起，需求设备类型临时冻结 | 不允许修改需求设备类型 |
| `HARD_LOCKED` | 已到授权书创建审批 06 节点或后续关键节点，需求设备类型硬锁定 | 不允许修改需求设备类型 |

### 8.3 项目授权 OA 状态

| 状态 | 说明 |
|---|---|
| `NOT_STARTED` | 未发起项目授权流程 |
| `IN_PROGRESS` | 项目授权审批中 |
| `NODE_06_REACHED` | 已到授权书创建审批 06 节点 |
| `APPROVED` | 项目授权流程审批通过 |
| `REJECTED` | 流程驳回 |
| `CANCELED` | 流程撤回或作废 |

## 9. 字段范围

### 9.1 第一阶段必须同步给 OA 的字段

| 字段 | 属性名 | 来源 |
|---|---|---|
| 商机ID | `opportunityId` | 商机系统 |
| 商机报备流程号 | `reportFlowNo` | OA 回写 |
| 采购单位 | `company` | 商机系统最新值 |
| 项目名称 | `name` | 商机系统最新值 |
| 投标供应商名称 | `supplierCompany` | 商机系统最新值 |
| 行业 | `industry` | 商机系统最新值 |
| 需求设备类型 | `deviceTypes` | 商机系统最新值 |
| 需求设备品类型号 | `deviceModels` | 商机系统最新值 |
| 预估采购金额 | `estimatedPurchaseAmount` | 商机系统最新值 |
| 金额单位 | `estimatedPurchaseAmountUnit` | 商机系统最新值 |
| 是否需要唯一授权 | `requiresExclusiveAuthorization` | 商机系统最新值 |
| 需授权品类 | `authorizedCategories` | 商机系统最新值 |
| 是否可以提前写参数 | `canPrepareParams` | 商机系统最新值 |
| 预计交付时间 | `expectedDeliveryDate` | 商机系统最新值 |
| 预计投标截止时间 | `bidDeadline` | 商机系统最新值 |
| 提报人 | `submitterName` | 商机系统最新值 |
| 提报人企业微信ID | `submitterUserId` | 商机系统 |
| 设备需求版本号 | `deviceRequirementVersion` | 商机系统 |
| 需求设备类型锁定状态 | `deviceRequirementLockStatus` | 商机系统 |
| 最后编辑时间 | `lastEditDate` | 商机系统 |

### 9.2 同步版本与锁定字段

建议新增：

| 字段 | 类型 | 说明 |
|---|---|---|
| `deviceRequirementVersion` | Integer | OA 预填同步版本号，初始为 1 |
| `deviceRequirementLockStatus` | String | 需求设备类型锁定状态，`UNLOCKED` / `SOFT_LOCKED` / `HARD_LOCKED` |
| `deviceRequirementLockedByFlowNo` | String | 当前锁定需求设备类型的 OA 流程号 |
| `deviceRequirementLockedAtNode` | String | 锁定发生的 OA 节点，例如 `06` |
| `deviceRequirementLockedAt` | DateTime | 锁定时间 |
| `reportFlowNo` | String | 商机报备 OA 流程号 |
| `reportArchivedAt` | DateTime | 商机报备归档时间 |
| `bidDocumentFlowNo` | String | 项目授权 OA 流程号（底层变量名兼容保留） |

### 9.3 触发版本号递增的字段

以下字段变更时，`deviceRequirementVersion` 必须加 1：

- `deviceTypes`
- `deviceModels`
- `requiresExclusiveAuthorization`
- `authorizedCategories`
- `canPrepareParams`
- `supplierCompany`
- `estimatedPurchaseAmount`
- `estimatedPurchaseAmountUnit`
- `bidDeadline`

第一期锁定范围与版本范围分离：流程发起后临时冻结、06 节点硬锁定的字段只包括 `deviceTypes`。上表其他字段纳入版本号，是为了保证 OA 项目授权申请预填数据可追溯，但不在第一期锁定范围内。

`expectedDeliveryDate` 暂不纳入版本号递增，后续如项目授权申请流程明确依赖该字段，再补充纳入。

## 10. 接口需求

### 10.1 发起 OA 商机报备流程

接口建议：

```http
POST /api/oa/opportunities/{opportunityId}/report-flow/start
```

请求参数：

```json
{
  "userId": "wecom_user_id",
  "userName": "张三"
}
```

处理规则：

1. 校验当前用户是否有该商机编辑权限。
2. 校验商机是否已存在未完成的商机报备流程。
3. 调用 OA 发起商机报备流程。
4. 保存 OA 流程发起状态和发起快照。
5. 返回 OA 流程号或待归档标识。

### 10.2 OA 商机报备归档回调

接口建议：

```http
POST /api/oa/callback/report-flow/archived
```

请求参数：

```json
{
  "opportunityId": 1001,
  "reportFlowNo": "OA-BB-20260525-001",
  "status": "ARCHIVED",
  "archivedAt": "2026-05-25 20:30"
}
```

处理规则：

1. 根据 `opportunityId` 更新商机报备状态。
2. 保存 `reportFlowNo`。
3. 保存归档时间。
4. 写入系统活动记录。

### 10.3 项目授权前预填接口

OA 传入商机报备流程号，商机系统返回最新商机报备信息。

接口建议：

```http
GET /api/oa/report-flows/{reportFlowNo}/bid-document-prefill
```

响应示例：

```json
{
  "opportunityId": 1001,
  "reportFlowNo": "OA-BB-20260525-001",
  "company": "郑州市中心医院",
  "name": "郑州市中心医院遴选电商平台采购项目",
  "supplierCompany": "北京京东世纪信息技术有限公司",
  "industry": "医疗",
  "deviceTypes": "数码打印A3, 办公设备",
  "deviceModels": "A3复印机、A4打印机",
  "estimatedPurchaseAmount": 50,
  "estimatedPurchaseAmountUnit": "万元",
  "requiresExclusiveAuthorization": true,
  "authorizedCategories": "A3复印机",
  "canPrepareParams": true,
  "expectedDeliveryDate": "2026-07-01",
  "bidDeadline": "2026-06-20",
  "submitterName": "张三",
  "submitterUserId": "zhangsan",
  "deviceRequirementVersion": 4,
  "deviceRequirementLockStatus": "UNLOCKED",
  "lastEditDate": "2026-05-25 21:20",
  "editableInOa": false
}
```

异常响应：

| 场景 | 处理 |
|---|---|
| 找不到 `reportFlowNo` | 返回 404，提示未找到商机报备流程 |
| 商机报备未归档 | 返回 409，提示商机报备流程未归档 |
| 需求设备类型已硬锁定 | 返回数据，但标记 `deviceRequirementLockStatus = HARD_LOCKED` |
| 商机已删除或作废 | 返回 409，提示商机不可用 |

### 10.4 OA 项目授权流程发起回调

接口建议：

```http
POST /api/oa/callback/bid-document-flow/started
```

请求参数：

```json
{
  "reportFlowNo": "OA-BB-20260525-001",
  "bidDocumentFlowNo": "OA-TB-20260525-009",
  "deviceRequirementVersion": 4,
  "startedAt": "2026-05-25 21:40"
}
```

处理规则：

1. 根据 `reportFlowNo` 找到商机。
2. 校验当前需求设备类型锁定状态不是 `HARD_LOCKED`。
3. 校验 OA 发起时使用的 `deviceRequirementVersion` 等于商机系统当前版本。
4. 校验通过后设置 `deviceRequirementLockStatus = SOFT_LOCKED`，临时冻结需求设备类型字段。
5. 保存 `bidDocumentFlowNo`。
6. 写入活动记录和修订记录。

如果版本不一致：

- 返回 409。
- 提示 OA 重新调用预填接口同步最新商机数据。

### 10.5 OA 到达授权书创建审批 06 节点回调

接口建议：

```http
POST /api/oa/callback/bid-document-flow/node-reached
```

请求参数：

```json
{
  "bidDocumentFlowNo": "OA-TB-20260525-009",
  "nodeCode": "06",
  "nodeName": "授权书创建审批",
  "arrivedAt": "2026-05-26 10:00"
}
```

处理规则：

1. 根据 `bidDocumentFlowNo` 找到商机。
2. 如果 `nodeCode = 06`，设置 `deviceRequirementLockStatus = HARD_LOCKED`，硬锁定需求设备类型字段。
3. 保存 `deviceRequirementLockedAtNode = 06`。
4. 保存锁定时间。
5. 写入活动记录。

### 10.6 OA 流程撤回、驳回或作废回调

接口建议：

```http
POST /api/oa/callback/bid-document-flow/status-changed
```

请求参数：

```json
{
  "bidDocumentFlowNo": "OA-TB-20260525-009",
  "status": "REJECTED",
  "changedAt": "2026-05-26 11:30",
  "reason": "资料不完整"
}
```

处理规则：

| OA 状态 | 商机系统处理 |
|---|---|
| `REJECTED` | 如果当前是 `SOFT_LOCKED`，必须解除需求设备类型冻结 |
| `CANCELED` | 如果当前是 `SOFT_LOCKED`，必须解除需求设备类型冻结 |
| `APPROVED` | 保持当前锁定状态，不自动解锁 |
| `NODE_06_REACHED` | 转为 `HARD_LOCKED` |

### 10.7 OA 接口鉴权与网关

OA 与商机系统通过企业内部统一网关调用接口。接口鉴权、签名、超时、重试、错误码等细节以 OA 标准接口文档为准，商机系统不单独设计固定密钥或 IP 白名单方案。

## 11. 手机端交互需求

### 11.1 需求设备类型可编辑状态

当 `deviceRequirementLockStatus = UNLOCKED`：

- 用户有权限时可以修改设备需求字段。
- 修改后生成字段级修订记录。
- 修改后 `deviceRequirementVersion + 1`。

当 `deviceRequirementLockStatus = SOFT_LOCKED`：

- 需求设备类型字段置灰。
- 页面提示：项目授权流程已发起，需求设备类型暂不可修改。

当 `deviceRequirementLockStatus = HARD_LOCKED`：

- 需求设备类型字段置灰。
- 页面提示：已进入授权书创建审批关键节点，需求设备类型已锁定。

### 11.2 修订记录展示

商机详情中需要展示：

- 修改字段。
- 修改前值。
- 修改后值。
- 修改人。
- 修改时间。
- 修改来源：手机端 / PC 端 / OA 回写 / 系统锁定。
- 设备需求版本号。

### 11.3 OA 关联信息展示

商机详情中建议展示：

- 商机报备 OA 流程号。
- 商机报备归档状态。
- 项目授权 OA 流程号。
- 设备需求锁定状态。
- 当前设备需求版本号。

## 12. 权限规则

1. 普通用户只能修改自己有权限的商机。
2. 领导或授权用户可按白名单规则修改可编辑范围内的商机。
3. 管理员可查看全部商机和全部 OA 同步记录。

## 13. 风险与边界

### 13.1 OA 归档快照不是最新数据

风险：项目授权流程如果直接读取 OA 商机报备归档表单，会拿到旧设备类型。

处理：项目授权流程发起前必须调用商机系统预填接口。

### 13.2 流程发起后用户继续改字段

风险：OA 表单和商机系统主数据不一致。

处理：项目授权流程发起回调成功后，商机系统将需求设备类型字段设为 `SOFT_LOCKED`。

### 13.3 OA 发起时拿到旧版本

风险：用户刚刚修改设备类型，OA 表单仍使用旧版本。

处理：OA 发起回调必须携带 `deviceRequirementVersion`，商机系统校验版本一致后才冻结。

### 13.4 授权管理人员私下改最终设备类型

### 10.4 OA 项目授权流程发起回调

接口建议：

```http
POST /api/oa/callback/bid-document-flow/started
```

请求参数：

```json
{
  "reportFlowNo": "OA-BB-20260525-001",
  "bidDocumentFlowNo": "OA-TB-20260525-009",
  "deviceRequirementVersion": 4,
  "startedAt": "2026-05-25 21:40"
}
```

处理规则：

1. 根据 `reportFlowNo` 找到商机。
2. 校验当前需求设备类型锁定状态不是 `HARD_LOCKED`。
3. 校验 OA 发起时使用的 `deviceRequirementVersion` 等于商机系统当前版本。
4. 校验通过后设置 `deviceRequirementLockStatus = SOFT_LOCKED`，临时冻结需求设备类型字段。
5. 保存 `bidDocumentFlowNo`。
6. 写入活动记录和修订记录。

如果版本不一致：

- 返回 409。
- 提示 OA 重新调用预填接口同步最新商机数据。

### 10.5 OA 到达授权书创建审批 06 节点回调

接口建议：

```http
POST /api/oa/callback/bid-document-flow/node-reached
```

请求参数：

```json
{
  "bidDocumentFlowNo": "OA-TB-20260525-009",
  "nodeCode": "06",
  "nodeName": "授权书创建审批",
  "arrivedAt": "2026-05-26 10:00"
}
```

处理规则：

1. 根据 `bidDocumentFlowNo` 找到商机。
2. 如果 `nodeCode = 06`，设置 `deviceRequirementLockStatus = HARD_LOCKED`，硬锁定需求设备类型字段。
3. 保存 `deviceRequirementLockedAtNode = 06`。
4. 保存锁定时间。
5. 写入活动记录。

### 10.6 OA 流程撤回、驳回或作废回调

接口建议：

```http
POST /api/oa/callback/bid-document-flow/status-changed
```

请求参数：

```json
{
  "bidDocumentFlowNo": "OA-TB-20260525-009",
  "status": "REJECTED",
  "changedAt": "2026-05-26 11:30",
  "reason": "资料不完整"
}
```

处理规则：

| OA 状态 | 商机系统处理 |
|---|---|
| `REJECTED` | 如果当前是 `SOFT_LOCKED`，必须解除需求设备类型冻结 |
| `CANCELED` | 如果当前是 `SOFT_LOCKED`，必须解除需求设备类型冻结 |
| `APPROVED` | 保持当前锁定状态，不自动解锁 |
| `NODE_06_REACHED` | 转为 `HARD_LOCKED` |
