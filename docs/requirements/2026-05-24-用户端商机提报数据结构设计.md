# 用户端商机提报数据结构设计

日期：2026-05-24

## 1. 背景

用户需要通过前端系统提报商机数据，提报渠道包括手机端和 PC 端。后台管理人员需要查看、筛选、管理所有用户提报的数据。

历史文档已基于 Excel `商机池` 设计过完整设备事业群商机字段。经业务确认，手机端和 PC 端用户提报时都需要填写 Excel 中所有字段信息。系统通过分步表单、草稿保存、默认值、字典选择、附件上传和企业微信提醒降低填写与跟进负担，而不是减少字段。

本次需求将商机提报数据拆为三类：

1. 用户需填写字段：Excel 商机池中需要用户提报的业务字段，手机端和 PC 端都要支持。
2. 管理员维护字段：设备类型、授权品类等字典/选项由管理员维护，提报用户从已有选项中选择。
3. 系统自动字段：提报人、提报日期、最后编辑时间、提醒时间、进度提醒等由系统生成或触发。

## 2. 已确认业务口径

1. 手机端也需要填写 Excel 中所有字段信息。
2. 用户提报后暂时不需要审核。
3. 普通用户都是企业在职员工，均通过企业微信登录。
4. 普通用户提交后有权限编辑自己的商机；领导或授权用户可查看、编辑白名单人员商机。
5. 需要做权限管控：普通用户只管理自己的商机，领导或授权用户管理白名单范围内商机，管理员管理全部。
6. 金额单位最终不确定，不能强制写死为万元，需要记录金额单位。
7. 设备类型、授权品类属于管理员维护信息，初始可采用 Excel 现有值。
8. 需要重复提报检测。
9. 需要附件上传。
10. 商机进度需要通过企业微信提醒用户，方便持续跟进项目。

## 3. 设计目标

1. 支持手机端、PC 端双渠道提报。
2. 用户端字段完整覆盖 Excel 商机池，同时通过交互设计提高填写效率。
3. 数据结构兼容 Excel 商机池字段，不与上一版设备事业群字段改造冲突。
4. 后台管理端可查看全量字段、筛选、编辑、补齐、导出。
5. 支持数据完整性、权限控制、附件追溯、重复检测和企业微信进度提醒。

## 4. 角色与渠道

| 角色 | 使用渠道 | 主要动作 |
|---|---|---|
| 提报用户/销售 | 手机端、PC 端 | 新增商机、编辑自己的商机、上传附件、更新进展 |
| 领导/授权用户 | 手机端、PC 端 | 查看和编辑白名单人员商机，查看修订记录 |
| 政企市场部经理 | PC 端为主 | 查看提报、补充评估、分派/确认 |
| 后台管理人员 | PC 管理端 | 查看全部数据、筛选、编辑、导出、统计、维护字典、配置提醒 |
| 省区/业务经理 | PC 端为主 | 按省区、设备品类、人员归属跟进 |

## 5. 用户端提报表单结构

### 5.1 手机端推荐结构

手机端采用分步/分组表单，覆盖 Excel 商机池所有字段。

步骤一：基础信息

- 采购单位
- 行业
- 项目名称
- 供应商公司名称(全称）
- 提报人
- 政企市场部经理
- 提报人省区
- 省区（供货省区）
- 销售部门
- 销售

步骤二：设备需求

- 需求设备类型
- 需求设备品类型号
- 需求数量
- 预估采购金额
- 预估采购金额单位

步骤三：授权与报备

- 是否可以提前写参数
- 是否需要唯一授权
- 需授权品类
- 是否报备成功

步骤四：投标与交付

- 赢率
- 预计交付时间
- 预计投标截止时间
- 是否中标
- 采购形式
- 项目中标金额
- 项目中标金额单位
- 得力设备BG交付金额
- 得力设备BG交付金额单位

步骤五：组织归属

- 省总
- A4业务经理
- A3业务经理

步骤六：进度与附件

- 本周项目进展/备注
- 附件上传

系统自动：

- 提报日期
- 提报人/创建人
- 最后编辑时间
- 提醒编辑时间
- 企业微信提醒状态

### 5.2 PC 端推荐结构

PC 端展示同样字段，但可以采用两栏布局和分组折叠：

- 基础信息
- 设备需求
- 授权与报备
- 投标与交付
- 组织归属
- 进度与附件
- 系统信息

PC 端适合批量编辑、附件管理、查看重复商机提示和历史跟进记录。

## 6. 字段设计

### 6.1 用户需填写字段

| 字段 | 属性名 | 类型 | 说明 |
|---|---|---|---|
| 提报人 | `submitter` | String | 默认取企业微信登录用户，可改为实际提报人 |
| 政企市场部经理 | `govMarketManager` | String | 从员工/组织字典选择 |
| 采购单位 | `company` | String | 客户/采购主体 |
| 行业 | `industry` | Enum/String | 政府、金融、医疗、教育等 |
| 项目名称 | `name` | String | 建议“地区 + 用户名称 + 具体采购产品” |
| 供应商公司名称(全称） | `supplierCompany` | String | 未确定时可填待定 |
| 提报人省区 | `submitterRegion` | String | 用户所在省区 |
| 省区（供货省区） | `supplyRegion` | String | 实际供货归属 |
| 需求设备类型 | `deviceTypes` | MultiSelect | 管理员维护选项，初始采用 Excel 现有值 |
| 需求设备品类型号 | `deviceModels` | String | 型号、品类描述 |
| 需求数量（台） | `demandQuantity` | Integer | 设备数量 |
| 预估采购金额 | `estimatedPurchaseAmount` | Decimal | 金额单位未最终确定，需记录单位 |
| 预估采购金额单位 | `estimatedPurchaseAmountUnit` | Enum | 元/万元，默认按系统配置 |
| 是否可以提前写参数 | `canPrepareParams` | Boolean | 是/否 |
| 赢率 | `winRateLabel` | Enum | 使用 Excel 枚举 |
| 是否需要唯一授权 | `requiresExclusiveAuthorization` | Boolean | 是/否 |
| 需授权品类 | `authorizedCategories` | MultiSelect | 管理员维护选项，初始采用 Excel 现有值 |
| 预计交付时间 | `expectedDeliveryDate` | Date | 交付计划 |
| 预计投标截止时间 | `bidDeadline` | Date | 投标截止日期 |
| 是否中标 | `bidWon` | Boolean/Enum | 是/否/未确定 |
| 采购形式 | `purchaseType` | Enum | 一次性/带量/框采/电商平台 |
| 项目中标金额 | `winningAmount` | Decimal | 中标后填写，需记录单位 |
| 项目中标金额单位 | `winningAmountUnit` | Enum | 元/万元 |
| 得力设备BG交付金额 | `deliBgDeliveryAmount` | Decimal | 交付后填写，需记录单位 |
| 得力设备BG交付金额单位 | `deliBgDeliveryAmountUnit` | Enum | 元/万元 |
| 销售部门 | `salesDepartment` | String | 用户选择或系统默认 |
| 是否报备成功 | `reportedSuccessfully` | Boolean/Enum | 是/否/未报备 |
| 销售 | `sales` | String | 负责销售 |
| 省总 | `provinceGeneralManager` | String | 从员工/组织字典选择 |
| A4业务经理 | `a4BusinessManager` | String | 从员工/组织字典选择 |
| A3业务经理 | `a3BusinessManager` | String | 从员工/组织字典选择 |
| 本周项目进展/备注 | `weeklyProgress` | Text | 承接 Excel 中“每周更新进展”规则 |

### 6.2 管理员维护字段

以下不是单条商机的填写字段，而是供用户选择的基础数据：

| 字段 | 属性名 | 类型 | 说明 |
|---|---|---|---|
| 需求设备类型字典 | `deviceTypeOptions` | Dictionary | 管理员维护，初始值采用 Excel 现有值 |
| 授权品类字典 | `authorizedCategoryOptions` | Dictionary | 管理员维护，初始值采用 Excel 现有值 |
| 行业字典 | `industryOptions` | Dictionary | 管理员维护，初始值采用 Excel 高频值 |
| 采购形式字典 | `purchaseTypeOptions` | Dictionary | 管理员维护，初始值采用 Excel 现有值 |
| 省区/供货省区字典 | `regionOptions` | Dictionary | 管理员维护 |
| 员工/组织字典 | `employeeOptions` | Dictionary | 来源企业微信通讯录或后台导入 |

### 6.3 系统自动字段

| 字段 | 属性名 | 类型 | 说明 |
|---|---|---|---|
| 提报日期 | `submitDate` | Date | 系统生成 |
| 提报人/创建人 | `creator` | String | 企业微信登录用户 |
| 最后编辑时间 | `lastEditDate` | DateTime | 系统更新 |
| 最后编辑人 | `lastEditor` | String | 企业微信登录用户 |
| 提醒编辑时间 | `remindEditDate` | Date | 根据最后编辑时间自动计算 |
| 商机阶段 | `stage` | Enum | 兼容旧 CRM 阶段 |
| 业务进度 | `businessProgressStatus` | Enum | 用于商机进度提醒 |
| 进度提醒状态 | `reminderStatus` | Enum | 未提醒/已提醒/已逾期/已关闭 |
| 数字/数字2/日期/文本/单选/日期2 | `legacyExtraJson` | JSON/Text | Excel 未确认字段暂存 |

- 政府

- 电信

- 其他

## 9. 管理端功能需求

### 9.1 列表查看

后台管理人员可查看所有用户提报数据，默认按提报日期倒序。

推荐列表字段：

- 提报日期
- 提报人/创建人
- 采购单位
- 项目名称
- 行业
- 需求设备类型
- 预估采购金额及单位
- 赢率
- 业务进度
- 提报人省区
- 供货省区
- 采购形式
- 是否报备成功
- 是否中标
- 最后编辑时间

### 9.2 筛选查询

必须支持：

- 关键词：采购单位、项目名称、供应商、型号
- 提报日期范围
- 行业
- 提报人省区
- 供货省区
- 需求设备类型
- 赢率
- 业务进度
- 采购形式
- 是否需要唯一授权
- 是否报备成功
- 是否中标
- 销售/提报人

### 9.3 管理编辑

后台管理人员可以：

- 编辑全部商机字段。
- 管理设备类型、授权品类、行业、采购形式、省区、人员等基础字典。
- 标记报备成功。
- 标记中标/未中标。
- 填写中标金额和 BG 交付金额。
- 配置企业微信提醒规则。
- 查看字段变更、附件和跟进日志。

### 9.4 数据追溯

每条提报至少保留：

- 创建人
- 创建时间
- 最后编辑人
- 最后编辑时间
- 关键字段变更记录
- 跟进记录
- 附件上传记录
- 企业微信提醒记录

## 10. 权限管控

### 10.1 登录身份

普通用户均为企业在职员工，通过企业微信登录。系统应保存企业微信用户标识、姓名、部门、省区等信息，用于自动填充提报人、创建人和权限判断。

### 10.2 普通用户权限

普通用户可以：

- 新增商机提报。
- 查看自己创建/提报/负责的商机。
- 编辑自己创建/提报/负责的商机。
- 上传、删除自己提报商机的附件。
- 追加跟进进展。

普通用户不应编辑：

- 他人提报的商机。
- 系统自动字段。
- 管理员锁定的关键字段。

领导或授权用户可以：

- 查看自己的商机。
- 查看白名单人员的商机。
- 编辑白名单人员商机的所有字段。
- 查看白名单范围内商机的字段级修订记录。

### 10.3 管理员权限

管理员可以：

- 查看全部商机。
- 编辑全部商机。
- 管理字典和选项。
- 查看附件和变更记录。
- 配置企业微信提醒规则。

### 10.4 后续可扩展权限

后续可按省区、部门、角色扩展：

- 省区负责人查看本省区数据。
- A4/A3 业务经理查看对应产品线数据。
- 政企市场部经理查看分管范围数据。

## 11. 重复提报检测

系统需要在用户提交和保存时进行重复提报检测。

### 11.1 推荐匹配规则

强匹配：

- 采购单位 + 项目名称 + 供货省区

弱匹配：

- 采购单位 + 需求设备类型 + 预计投标截止时间
- 项目名称相似 + 供应商公司名称相似
- 采购单位相同 + 设备型号相同 + 金额接近

### 11.2 交互规则

当检测到疑似重复时：

- 不强制阻止提交。
- 提示用户“可能已有相似商机”。
- 展示相似商机的项目名称、采购单位、提报人、提报日期、当前进度。
- 用户可选择继续提交或返回修改。

管理员端需要支持重复商机合并/标记。

## 12. 附件上传

商机提报需要支持附件上传。

### 12.1 附件类型

建议支持：

- 招标公告
- 参数文件
- 授权材料
- 报备材料
- 报价文件
- 合同/中标通知
- 项目截图
- 其他附件

### 12.2 附件字段

| 字段 | 属性名 | 类型 | 说明 |
|---|---|---|---|
| 附件ID | `id` | Long | 系统生成 |
| 商机ID | `opportunityId` | Long | 关联商机 |
| 文件名 | `fileName` | String | 原始文件名 |
| 文件地址 | `fileUrl` | String | 存储地址 |
| 文件类型 | `fileType` | String | 附件业务类型 |
| 上传人 | `uploadedBy` | String | 企业微信用户 |
| 上传时间 | `uploadedAt` | DateTime | 系统生成 |

### 12.3 权限规则

- 普通用户只能管理自己有权限商机的附件。
- 领导或授权用户可管理白名单范围内商机附件。
- 管理员可查看和管理全部附件。
- 已归档或锁定商机的附件删除需管理员权限。

## 13. 企业微信进度提醒

商机进度需要通过企业微信提醒用户，帮助用户持续跟进项目。

### 13.1 提醒触发场景

建议第一期支持：

- 提报成功提醒：提交后发送给提报人。
- 投标截止提醒：投标截止前 N 天提醒。
- 预计交付提醒：预计交付前 N 天提醒。
- 周更新提醒：距离最后编辑时间超过 7 天提醒提报人更新进展。
- 授权跟进提醒：需要唯一授权但授权品类未填或授权材料未上传时提醒。
- 报备提醒：未报备成功且临近投标截止时提醒。
- 中标结果提醒：投标截止后仍未填写是否中标时提醒。

### 13.2 提醒对象

默认提醒：

- 提报人/创建人
- 销售

可扩展提醒：

- 政企市场部经理
- 省总
- A4业务经理
- A3业务经理

### 13.3 提醒配置

建议管理员可配置：

- 投标截止提前提醒天数，默认 3 天。
- 预计交付提前提醒天数，默认 3 天。
- 周更新周期，默认 7 天。
- 是否重复提醒。
- 逾期提醒频率。

### 13.4 提醒内容

企业微信提醒应包含：

- 项目名称
- 采购单位
- 当前赢率/阶段
- 待处理事项
- 截止时间
- 商机详情链接

## 14. 与历史方案的冲突分析

### 14.1 不冲突点

- 字段仍然兼容 Excel 商机池。
- `Opportunity` 仍作为核心实体。
- `winRateLabel`、`weeklyProgress` 等字段沿用上一版命名。
- 管理端仍可维护完整字段、字典、筛选和统计。

### 14.2 需要调整的点

| 历史方案 | 本次调整 | 原因 |
|---|---|---|
| 用户端只录入必填 + 选填，管理端维护全量 | 手机端和 PC 端都支持填写 Excel 全字段 | 业务要求提报数据完整 |
| `POST /api/opportunities` 直接创建商机 | 建议新增 `POST /api/opportunities/submissions` | 区分用户提报和管理端创建 |
| 金额字段按万元命名 | 新增金额单位字段，金额单位不强行确定 | 业务确认最终单位暂不确定 |
| `owner` 默认映射销售 | 用户端创建时可先为空或等于 creator，后台再分派 sales/owner | 避免提报人与销售概念混淆 |
| 无附件模型 | 新增附件上传 | 满足招标、授权、报备材料追溯 |
| 无提醒流程 | 新增企业微信进度提醒 | 保障商机持续跟进 |

## 15. 企业微信身份与移动端权限控制

### 15.1 背景与目标

手机端需要实现商机提报和商机看板。商机看板必须基于企业微信身份做数据隔离，不能只依赖前端筛选或用户姓名判断权限。

目标：

1. 通过企业微信账户识别用户身份。
2. 手机端只保留一个入口：`我的商机`。
3. `我的商机` 的数据范围由后端权限配置决定。
4. 管理员可以通过用户板块维护角色和白名单。
5. 领导或被授权用户可查看、编辑白名单人员的商机。
6. 所有编辑都必须生成字段级修订记录。

### 15.2 登录与用户来源

第一期：

- 手机端先使用沙箱模拟登录。
- 系统预留真实企业微信 SSO 接入。

后续真实接入：

- 系统调用企业微信 API 自动同步企业微信组织架构、用户、部门、标签。
- 企业微信 `wecomUserId` 是权限判断的唯一身份标识。
- 用户姓名只用于展示，不用于权限判断。
- 用户改名后，展示姓名跟随用户表最新姓名。

企业微信真实接入需要配置：

- `CorpID`
- 通讯录 `Secret`
- 应用 `AgentID`
- 应用 `Secret`
- 可信域名
- 回调地址
- 通讯录读取权限

### 15.3 用户板块

需要新增用户板块，用于展示企业微信同步过来的人员，并维护角色、状态和白名单权限。

用户基础字段建议：

| 字段 | 属性名 | 说明 |
|---|---|---|
| 企业微信用户ID | `wecomUserId` | 权限判断唯一依据 |
| 姓名 | `name` | 展示名称，可随企业微信同步更新 |
| 手机号 | `mobile` | 可选 |
| 邮箱 | `email` | 可选 |
| 部门ID | `departmentId` | 企业微信部门ID |
| 部门名称 | `departmentName` | 企业微信部门名称 |
| 职位 | `position` | 企业微信职位 |
| 用户状态 | `status` | 在职/离职/禁用 |
| 角色 | `role` | 普通用户/领导/管理员 |
| 是否查看全部 | `canViewAll` | 管理员或特殊授权 |
| 是否启用 | `enabled` | 禁用用户不允许登录 |

管理员识别规则：

- 管理员可手动配置。
- 管理员也可根据企业微信部门或标签自动识别。
- 手动配置应可覆盖自动识别结果。

### 15.4 白名单权限

第一期只做用户白名单，不做部门批量授权。

白名单配置方式：

- `领导/授权用户 -> 可查看人员列表`
- 白名单页面仅管理员可用。
- 领导不能自行配置自己的白名单。

白名单权限范围：

- 白名单影响手机端 `我的商机`、列表和看板的数据可见范围。
- 白名单也允许领导或被授权用户编辑这些人员的商机。
- 第一期白名单查看和编辑范围保持一致。
- 数据结构建议预留查看范围和编辑范围拆分能力，以便后续支持“可看不可改”。

### 15.5 商机归属字段

商机表需要新增稳定身份字段，避免仅用姓名做权限判断。

建议字段：

| 字段 | 属性名 | 说明 |
|---|---|---|
| 创建人企业微信ID | `creatorUserId` | 创建商机的企业微信用户ID |
| 创建人姓名 | `creatorName` | 展示用，可跟随用户表更新 |
| 提报人企业微信ID | `submitterUserId` | 提报人企业微信用户ID |
| 提报人姓名 | `submitterName` | 展示用 |
| 负责人企业微信ID | `ownerUserId` | 负责人企业微信用户ID |
| 负责人姓名 | `ownerName` | 展示用 |
| 归属状态 | `visibilityStatus` | `ASSIGNED` / `UNASSIGNED` |

历史 Excel 导入数据处理：

- 由于历史 Excel 数据没有企业微信 `wecomUserId`，第一期先标记为 `UNASSIGNED`。
- `UNASSIGNED` 数据仅管理员可见。
- 后续可在用户板块中通过姓名映射或人工归属，把历史数据补齐到具体企业微信用户。

### 15.6 手机端“我的商机”数据范围

手机端只保留一个入口：`我的商机`。

后端根据当前企业微信用户计算可见范围：

1. 如果当前用户是管理员或 `canViewAll = true`，返回全部商机。
2. 如果当前用户是普通用户或领导，返回：
   - `creatorUserId = 当前 wecomUserId`
   - 或 `submitterUserId = 当前 wecomUserId`
   - 或 `ownerUserId = 当前 wecomUserId`
   - 或 `creatorUserId / submitterUserId / ownerUserId` 属于当前用户白名单人员。
3. 普通用户和领导默认不返回 `UNASSIGNED` 历史数据。

### 15.7 编辑权限

编辑权限由后端强制判断，不能只依赖前端按钮隐藏。

规则：

- 普通用户可编辑自己的商机。
- 领导或被授权用户可编辑白名单人员商机的所有字段。
- 管理员可编辑全部商机。
- 离职/禁用用户本人不能登录和编辑。
- 离职/禁用用户的历史商机仍保留，管理员和有白名单权限的领导仍可查看。

### 15.8 字段级修订记录

所有商机编辑必须写入字段级修订记录。

修订记录建议字段：

| 字段 | 属性名 | 说明 |
|---|---|---|
| 商机ID | `opportunityId` | 被修改的商机 |
| 修改人企业微信ID | `editorUserId` | 实际修改人 |
| 修改人姓名 | `editorName` | 展示用 |
| 修改时间 | `editedAt` | 系统生成 |
| 字段名 | `fieldName` | 被修改字段 |
| 字段标题 | `fieldLabel` | 展示用中文字段名 |
| 修改前 | `oldValue` | 修改前值 |
| 修改后 | `newValue` | 修改后值 |
| 修改来源 | `source` | 手机端/PC端/导入/系统 |
| 权限来源 | `permissionSource` | 本人/白名单/管理员 |
| 原商机归属人 | `ownerUserId` | 便于追责 |

修订记录展示：

- 普通用户可查看自己有权限商机的修订记录。
- 领导可查看白名单范围内商机的修订记录。
- 管理员可查看全部修订记录。

## 16. 产品验收标准

1. 手机端可通过分步表单填写 Excel 商机池全部字段。
2. PC 端可填写 Excel 商机池全部字段。
3. 用户端必填字段为空时阻止提交，并提示具体字段。
4. 普通用户可编辑自己的商机，不能编辑未授权商机。
5. 领导或授权用户可查看、编辑白名单人员商机。
6. 管理端可按核心条件筛选和搜索。
7. 系统自动生成提报日期、创建人、最后编辑时间。
8. 系统支持重复提报检测和相似商机提示。
9. 系统支持附件上传、查看和权限控制。
10. 系统可按投标截止、预计交付、周更新、授权、报备、中标结果等场景发送企业微信提醒。
11. 数据字段兼容 Excel 商机池核心字段。
12. 不破坏既有商机列表、看板、详情、仪表盘能力。
13. 手机端提供 `我的商机` 入口，后端按企业微信 `wecomUserId` 强制过滤数据。
14. 管理员可在用户板块查看企业微信同步用户，并维护角色、启用状态和白名单。
15. 领导或授权用户可查看、编辑白名单人员商机。
16. 历史未归属商机仅管理员可见。
17. 所有商机编辑均生成字段级修订记录，且有权限用户可在详情中查看。

## 17. 风险点

1. 手机端填写 Excel 全字段会增加表单长度，需要草稿保存、分步表单、默认值、字典选择降低负担。
2. 金额单位最终未确定，必须在每个金额字段记录单位，否则统计会失真。
3. 普通用户、领导和管理员的编辑范围不同，需要字段级权限和修改日志，避免关键字段被误改且不可追责。
4. 设备类型和授权品类由管理员维护，若字典不及时维护，会影响用户提报准确性。
5. 重复提报检测如果过严会阻止真实不同商机，如果过松会产生重复数据。
6. 附件上传涉及文件大小、格式、安全扫描和存储成本。
7. 企业微信提醒如果频率过高会打扰用户，需要可配置和可关闭规则。
8. 如果只依赖前端筛选或姓名字段做权限判断，会产生越权访问风险；必须以后端 `wecomUserId` 强制过滤。
9. 企业微信组织架构同步失败时，需要保留上一次可用的用户数据，并提示管理员同步状态。
10. 白名单允许编辑所有字段，必须依赖字段级修订记录保证可追责。
11. 历史 Excel 数据第一期未归属，普通用户可能看不到历史商机，需要后续提供归属映射能力。
