# 手机端信息架构与核心页面需求

日期：2026-05-26

## 1. 背景

当前系统已经具备手机端访问能力，现有导航中包含工作台（原仪表盘）、商机看板、商机列表、商机提报和系统设置等入口。结合业务使用方式与手机端访问场景，现阶段需要重新整理手机端信息架构，明确一级导航、页面职责、权限边界和第一期交付范围。

本次整理目标不是增加新的后台能力，而是把手机端真正高频、刚需、可持续使用的能力收敛清楚，避免页面职责重叠、导航命名不贴近业务、普通用户误入后台管理功能等问题。

## 2. 目标

手机端第一期的目标是形成一个可稳定使用的业务闭环，让销售和业务人员能够在手机上完成以下核心动作：

1. 登录系统并识别当前身份。
2. 查看个人相关的商机摘要和待跟进事项。
3. 按阶段查看有权限的商机。
4. 搜索和筛选商机。
5. 新增商机提报。
6. 查看个人信息并支持退出登录。

同时，管理员仍可在手机端进入管理相关页面，但管理能力不应占据普通用户的一级导航主入口。

## 3. 核心结论

手机端一级导航建议统一调整为：

- 工作台
- 商机提报
- 商机列表
- 商机看板
- 用户中心

其中：

1. `工作台` 作为原 `仪表盘` 的最终业务命名，负责摘要、提醒和快捷入口。
2. `用户中心` 负责登录状态、个人信息、权限说明和退出登录。
3. `系统设置` 保留为管理员专属入口，不直接作为普通用户一级导航项暴露。
4. 管理员相关入口可以收纳在 `用户中心` 和管理员专属工作区入口内部。
5. `工作台`、`商机看板`、`商机列表` 三者必须明确分工，避免用户认为是三套重复页面。

## 4. 适用角色

| 角色 | 手机端主要目标 |
|---|---|
| 普通用户/销售 | 登录、查看我的数据、搜索商机、提报商机、编辑自己有权限的商机、退出登录 |
| 领导/授权用户 | 查看自己的数据、查看白名单范围商机、编辑白名单范围商机、查看个人权限说明 |
| 管理员 | 使用普通用户能力，并可从用户中心进入管理入口 |

## 5. 手机端信息架构

### 5.1 一级导航

建议底部导航固定为以下五项：

1. 工作台
2. 商机提报
3. 商机列表
4. 商机看板
5. 用户中心

规则：

- 一级导航数量控制在 5 项，`系统设置` 不进入普通用户底部导航。
- 图标和文案需要稳定、易懂，避免“设置”与“个人中心”混淆。
- 一级导航默认对所有登录用户可见。
- 管理员功能不新增单独底部 Tab，而是放入用户中心内二级入口。

### 5.2 二级页面结构

建议手机端主要结构如下：

- 工作台
  - 我的商机摘要
  - 重点提醒
  - 快捷入口
- 商机提报
  - 分步表单
  - 草稿
  - 重复校验
  - 提交结果
- 商机列表
  - 搜索
  - 筛选
  - 结果列表
  - 商机详情入口
- 商机看板
  - 按阶段查看商机
  - 商机详情入口
- 用户中心
  - 当前用户信息
  - 权限说明
  - 登录状态
  - 退出登录
  - 管理入口（管理员可见）

## 6. 页面职责定义

### 6.1 工作台

定位：

面向“今天要做什么”的首页，不承担复杂管理和全量检索。

建议展示内容：

- 我的商机总数
- 进行中商机数
- 本月新增商机数
- 即将到期商机数
- 中标/丢单概览
- 待更新进展提醒
- 快捷跳转到“商机提报”“商机列表”“商机看板”

边界：

- 不承担复杂筛选。
- 不承担完整列表浏览。
- 不替代看板和列表。

### 6.2 商机看板

定位：

面向“推进过程”的页面，按业务阶段查看商机分布。

核心能力：

- 按阶段展示当前用户有权限查看的商机
- 点击卡片进入商机详情
- 允许查看关键字段摘要

第一期建议：

- 优先保证看板浏览和详情跳转可用
- 阶段拖拽更新可作为增强能力分期实现

边界：

- 不承担复杂搜索和多条件过滤
- 不替代列表页的精确检索能力

### 6.3 商机列表

定位：

面向“查找和筛选”的页面，是手机端最核心的检索入口。

核心能力：

- 关键词搜索
- 多维筛选
- 结果列表浏览
- 点击进入详情

第一期建议至少支持以下筛选条件：

- 关键词：采购单位、项目名称、供应商、型号
- 行业
- 供货省区
- 业务进度

后续可扩展：

- 提报日期范围
- 采购形式
- 是否报备成功
- 是否中标
- 设备类型

边界：

- 不承担个人账号信息管理
- 不承担复杂图表展示

### 6.4 商机提报

定位：

面向“新增商机”的高频业务入口。

核心能力：

- 分步填写完整字段
- 必填校验
- 重复商机检测
- 附件上传
- 提交成功反馈

强烈建议纳入第一期的体验能力：

- 草稿保存
- 默认值填充
- 字典选择
- 提交后引导查看刚提交的商机

边界：

- 不在本页面承担复杂审批流管理
- 不允许前端自行决定商机权限归属

### 6.5 用户中心

定位：

面向“我自己”的页面，承接身份、账号、权限说明和退出动作。

核心能力：

- 展示当前登录用户姓名、角色、部门或省区等基础信息
- 展示当前用户的权限范围说明
- 支持退出登录
- 支持未登录状态下进入登录流程

管理员附加能力：

- 用户管理入口
- 白名单配置入口
- 字典维护入口

结论：

- 普通用户关注的是“我是谁、我能看什么、怎么退出”
- 管理员关注的是“我还能进管理页”
- 因此 `用户中心` 比 `系统设置` 更符合手机端认知

## 7. 商机详情页补充要求

虽然商机详情不是一级导航，但它是看板、列表、提报后的共同落点，必须纳入手机端需求范围。

建议详情页至少包含：

- 基础信息
- 设备需求信息
- 跟进记录
- 待办任务
- 附件
- 修订记录
- OA 关联信息（如已接入）

规则：

- 看板和列表点击商机后进入统一详情页
- 详情页中由后端决定可查看和可编辑范围
- 修订记录仅展示当前用户有权限查看的商机内容

## 8. 登录与退出需求

### 8.1 登录

第一期口径：

- 手机端沿用企业微信沙箱模拟登录
- 预留真实企业微信 SSO 接入

登录要求：

- 未登录访问业务页时自动跳转登录页
- 登录成功后进入默认首页或返回目标页
- 禁用或离职用户不得登录

### 8.2 退出登录

退出登录必须作为手机端明确能力纳入需求。

退出要求：

- 在用户中心提供清晰可见的退出入口
- 退出后清理本地登录态和用户缓存
- 退出后跳转到登录页
- 退出后再次访问业务页时需要重新登录

## 9. 权限与可见范围

手机端页面必须遵循既有权限体系，不允许前端绕过后端权限判断。

规则：

1. 普通用户只能查看和编辑自己的商机。
2. 领导或授权用户可查看和编辑白名单范围内商机。
3. 管理员可查看和编辑全部商机。
4. 历史未归属商机仅管理员可见。
5. 管理端按钮隐藏只能改善体验，不能替代后端鉴权。

页面体现：

- 普通用户在用户中心不显示管理入口
- 管理员在用户中心显示管理入口
- 列表、看板、详情中的数据范围全部以接口返回为准

## 10. 移动端体验要求

基于当前手机端页面截图和业务场景，建议补充以下移动端约束：

1. 底部导航固定，不随页面内容滚动消失。
2. 列表筛选区默认可折叠，避免首屏被大面积筛选表单占满。
3. 长表单必须分步或分组，不应一次性平铺全部字段。
4. 看板卡片和列表项优先展示最关键字段，避免信息密度失控。
5. 页面在窄屏下不能出现横向滚动和文字遮挡。
6. 弱网或接口失败时要有明确提示和重试机制。
7. 空状态需要有清晰反馈，例如“暂无商机”“暂无筛选结果”。

## 11. 第一阶段建议范围

建议手机端第一阶段先完成以下 MVP 能力：

1. 登录
2. 退出登录
3. 工作台首页
4. 商机看板
5. 商机列表
6. 商机提报
7. 商机详情
8. 基础筛选
9. 权限隔离

建议放入第二阶段的增强能力：

1. 草稿自动保存
2. 更复杂的筛选组合
3. 看板拖拽改阶段
4. 更多图表分析
5. 更完整的消息提醒
6. 更多管理员配置能力

## 12. 非目标

本次手机端信息架构整理暂不包含以下内容：

1. 重构 PC 端整体导航
2. 新增复杂 BI 报表模块
3. 在手机端开放全部后台设置项
4. 引入多租户或跨组织能力
5. 改造 OA 全流程交互结构

## 13. 验收标准

完成后至少满足以下验收标准：

1. 手机端主导航调整为 `工作台 / 商机提报 / 商机列表 / 商机看板 / 用户中心`。
2. `系统设置` 保留为管理员专属入口，不进入普通用户五大主导航。
3. 未登录用户访问业务页面时会跳转登录页。
4. 登录用户可以从用户中心执行退出登录。
5. 退出后访问业务页需要重新登录。
6. 工作台、看板、列表三者页面职责清晰，不再承担高度重复功能。
7. 商机列表至少支持关键词、行业、供货省区、业务进度筛选。
8. 商机看板和商机列表都可以进入统一商机详情页。
9. 管理员可在用户中心或管理员专属入口看到系统设置与管理入口，普通用户不可见。
10. 手机端主要页面在常见窄屏下不出现明显遮挡、横向滚动和导航混乱。

## 14. 风险与注意事项

1. 如果继续保留“系统设置”作为普通用户一级导航，普通用户会误以为该页面是高频功能，容易与用户中心职责重叠。
2. 如果工作台、看板、列表不做边界划分，用户会感知为三个重复页面，降低使用效率。
3. 如果提报表单不支持分步、草稿、默认值，手机端完整填写体验会明显偏重。
4. 如果退出登录不明确，测试和多账号切换会非常不方便。
5. 如果管理员能力继续直接暴露在一级导航中，会干扰普通用户主流程。
